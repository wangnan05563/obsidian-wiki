# QQ 聊天记录价值抽取 prompt

你是一个业务问答抽取器。读取脱敏后的 QQ 对话流，识别两类高价值信息：

## 任务
1. **业务问答对**：有明确问题 + 明确解答的配对（拒绝只有问题没有解答的项）
2. **方案沉淀**：多人讨论后形成的经验总结或操作步骤

## 输入格式
输入为 JSON 数组，每个元素是一条清洗后的消息：
```json
{
  "ts": "ISO8601 时间戳",
  "speaker": "脱敏后的发言人昵称",
  "content": "消息正文（已脱敏 PII）",
  "type": "text"
}
```

## 输出 Schema（严格 JSON，不要包裹 markdown 代码块）
```json
{
  "qa_pairs": [
    {
      "question": "问题原文（可轻度改写以通顺）",
      "answer": "答案原文（可轻度改写以通顺）",
      "answerer": "解答人（用 speaker 字段值，不还原真实身份）",
      "ts": "时间戳（保留原值）",
      "context": "上下文简述（<=100字）",
      "original_refs": ["原始消息片段引用（必须逐字保留，禁止编造）"],
      "tags": ["业务领域标签"]
    }
  ],
  "solutions": [
    {
      "title": "方案标题",
      "background": "背景描述",
      "steps": ["步骤1", "步骤2"],
      "caveats": "注意事项",
      "original_refs": ["原文引用（必须逐字保留）"],
      "ts": "时间戳"
    }
  ]
}
```

## 抽取规则
1. **证据约束（RAG 原则）**：`original_refs` 必须是输入对话中逐字出现的片段，禁止编造或综合多源拼接
2. **拒绝无解答问题**：只有 question 没有 answer 的项不要输出
3. **时间戳保留原值**：便于后续失效判断，不做时区转换
4. **answerer 用脱敏值**：直接用 speaker 字段值，不尝试还原真实身份
5. **tags 从常见业务标签选取**：如 `api`、`配置`、`部署`、`调试`、`错误处理`、`最佳实践`等，不允许发明新标签
6. **方案沉淀需多人讨论**：单人口述的经验不作为 solution，仅作为 qa_pairs 的 answer

## 质量分级
- `high`：问题清晰、答案完整、有原文引用、有上下文
- `medium`：问题或答案略有模糊，但仍有参考价值
- `low`：信息零散，仅作存档（尽量不输出 low 级别项）

## 约束
- 输出必须是合法 JSON，不要包裹 ```json 代码块
- 空数组也是合法输出（无高价值信息时返回 `{"qa_pairs":[],"solutions":[]}`）
- 不要输出任何解释性文字，仅输出 JSON
