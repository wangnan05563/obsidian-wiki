# 同款产品调研与优化需求梳理（T01718，2026-10）

> 调研对象：GitHub 上与 karpathy-wiki 同类的知识库产品（本地双链笔记 / AI 知识库 / 协作知识库三类，共 16 个）。
> 目标：从「客户体验提升 / 功能扩展 / UI 升级 / 主题升级」四个维度梳理可落地的优化需求。
> 说明：本调研聚焦**产品层**，与 `docs/wiki-harness-开源调研与优化需求.md`（agent 框架层）互补不重叠。star 数与版本号为 2025-2026 第三方快照，可能有偏差，落地前建议核对官方 release 页。

## 一、调研范围与方法

- 三类同款产品并行调研（官方 release notes / changelog / 官网优先）：
  1. **本地优先双链笔记**：Obsidian、Logseq（DB 2.0 Beta）、SiYuan 思源、Joplin、Trilium/TriliumNext
  2. **AI 知识库 / Chat-with-notes**：Khoj、Reor、AnythingLLM、Cherry Studio、Open WebUI（重点 RAG）、LobeChat（重点知识库/TTS/插件）
  3. **协作 / 模块化知识库**：AFFiNE、AppFlowy、Outline、Docmost（Node 技术栈，重点参照）、Anytype
- 本项目现状基线：Vue3 + Element Plus + Pinia / Fastify + TS、本地 SQLite+文件、AI 问答 BYOK 多模型 + 流式可续传、TTS 聆听、移动端 5 Tab、主题（默认/macaron/ecommerce）、mermaid 渲染、QQ 摄取。

## 三、优化需求清单（按四维度，含优先级）

优先级口径：P0=直接提升核心体验/低成本高收益；P1=明显增强但需设计；P2=远期/锦上添花。每条标注来源竞品与本项目落地方式。**以下均为待评审清单项，经派生单评审排期后再逐条建任务。**

### A. 客户体验提升

| # | 需求 | 来源 | 优先级 | 落地方式 |
|---|---|---|---|---|
| A1 | **语义搜索**：搜索框混合关键词+向量结果（embedding+rerank，BYOK），并入快速切换器 | SiYuan / Joplin / Open WebUI | P0 | SQLite FTS5 做 BM25，向量走 BYOK embedding API 存本地，RRF 融合排序 |
| A2 | **命令面板统一入口**：切笔记+插入引用+执行命令合一，带路径面包屑消歧 | SiYuan / Obsidian / Outline | P1 | Vue3 全局浮层，el-autocomplete + 快捷键 Ctrl+K |
| A3 | **AI 问答稳健性**：回答可取消、失败停止自动重试、会话历史持久化 | Joplin | P0 | 复用现有流式续传（CODING-STREAMING-RESUME），补取消/重试语义 |

## 四、与本项目现状的映射与「不做」清单

- **已有可直接复用的地基**：流式续传（A3）、BYOK 多模型管理（C2）、`--menu-active-fg` 主题变量经验（D1/D2）、移动端 Shell（C6）、mcp-interface 设计（B6）、SQLite 池化（A1 存储层）。
- **坚持的路线**（Logseq DB 化争议的教训）：文件为本 + 索引库辅助，不把 Markdown 迁进专有库。
- **暂不做**：CRDT 多端实时同步（单机优先，等桌面壳定版）、实时协作、白板 Canvas（价值高但工程量大，单独立项）、fork Open WebUI（自定义 License，仅技术参考）。
- **安全红线承接**：A7 备份加密与 API Key 托管（Obsidian Keychain / Trilium keyring 思路）呼应「敏感字段加密」既有决策。

## 五、落地节奏建议

1. **第一批（P0）**：A1 语义搜索、B1 引用溯源、A3 问答稳健性、C1 思考折叠、D1+D2 主题变量架构+暗色模式 —— 全部命中现有地基，性价比最高。
2. **第二批（P1）**：A2 命令面板、A4 检索测试、A5 写作联想、B2 属性视图、B6 MCP server、C2 对话内换模型、D4 主题预览。
3. **第三批（P2 及观察项）**：其余。桌面壳（Electron/Tauri）定版后再评估 C5/C6。
