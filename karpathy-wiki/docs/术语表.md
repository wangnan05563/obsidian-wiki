## 2. 核心对象词

| 用户可见名 | 指什么 | 禁用别名 | 备注 |
|---|---|---|---|
| **页面** | 知识库内的产物（`concepts/`、`entities/` 等目录下的 Markdown 页） | 笔记、文档（指代知识库产物时）、条目 | 图谱节点、清洗列表、浏览树、批量进度一律用「页面」；量词用「个页面」 |
| **资料** | 尚未进入知识库的**外部输入**（上传文件、URL、文本、QQ 记录） | 素材、内容 | 「投递资料」是菜单名，也是这一层的统称 |
| **草稿** | 编译产出但尚未发布的页面 | 待发布文档 | 审核/发布动作作用于草稿，发布后称页面 |
| **知识库页面** | 「页面」的完整说法，用于首次出现的提示语 | 知识库文档 | |
| **外部文档** | 用户自己电脑上的 docx/pdf/网页等 | —— | 允许保留「技术文档 / Obsidian 笔记 / 记事本」等外部语境 |

豁免（可继续写「文档/笔记」的语境）：菜单名「帮助文档」；帮助页自述「本文档」；
来源类型标签「文档」（指上传的 Office/PDF 文件本身）；「Obsidian 笔记」「粘贴到记事本」等外部工具语境。

## 5. 动词与阶段名（编译链路）

编译阶段的**唯一中文来源是 `STEP_LABEL`**：
`存档原始资料 → 读取结构规范 → 抽取要点 → 生成页面 → 更新索引 → 记录日志 → 收尾`。

| 用户可见词 | 禁用别名 | 说明 |
|---|---|---|
| **抽取** | 提取（编译阶段语境） | LLM 从资料里取要点的动作；帮助文档描述阶段时必须用 STEP_LABEL 的原词 |
| **编译** | 转换、生成（指整条链路时） | 从资料到页面的全过程 |
| **发布** | 上线 | 草稿 → 页面 |
| **URL** | URI | 一律大写 URL |
| 生成页面 | 产出页面 | |
| 读取结构规范 | 读取结构、读取 SCHEMA | 面向用户不出现内部标识符（`read_schema` 等，PRD D3x） |

## 6. 状态与反馈词

| 场景 | 用户可见词 | 禁用 |
|---|---|---|
| 步骤/运行状态 | 完成 / 失败 / 运行中 | 裸枚举 `done`/`error`/`running` |
| 体检总态 | 系统状态良好 / 发现 N 个问题 · 需要处理 | ALL CLEAR / NEEDS ATTENTION |
| 加载中 | 「正在×××…」说清在加载什么对象（正在加载页面列表…），一律经 `StateBlock` 出口 | 裸「加载中…」、`LOADING...`、`SEARCHING...`、`// ×××中…` 装饰前缀 |
| 空态 | 一句现状 + 一句原因 + 一个主按钮（X8，`StateBlock state="empty"`） | 「暂无数据」后无下一步的死胡同 |
| 未保存标记 | 未保存 | `CHANGED` |
| 追问引导 | 你可能想问： | 追问：、猜猜你想问： |

已裁决豁免：`stepStatusLabel` 对**未知**枚举原样返回（T02459，便于定位脏数据）；
`store.stepLabel()` 对未知 key 返回原 key 同理。新枚举应在映射里补中文，而不是依赖兜底。

## 7. 技术词降级规则（PRD X10）

`token`、`maxSteps`、`tokenBudget`、`BYOK`、`frontmatter`、`config.json`、`OAuth`、`cert.pem`、
`SHA-256`、`JSONL`、`resume`、`[[链接]]` 一律**不得**作为主语出现在用户文案里：
正文写人话（如「元信息」代替 frontmatter、「上下文用量」代替 tokenBudget），原词进 tooltip 或「高级」折叠区。

## 8. 守护口径（可执行）

禁用别名清单的**机器可读版本**是 `docs/terminology-bans.json`（`term` / `why` / `exempt`），
前后端两个守护用例共用这一份，不允许各自再抄一份清单——两抄必分叉。新增禁用词：先改本表分组，
再往 JSON 的 `bans` 里加一条，两侧即刻生效。

- `frontend/test/terminology-single-source.test.ts`（T02475）扫描 `frontend/src` 全部 `.vue/.ts`；
- `api/test/terminology-bans.test.ts`（T02705）扫描 `api/src` 全部 `.ts`——后端的接口 `message` /
  `detail`、启动失败原因、修复日志条目会被前端原样 toast，属于用户可见文案，同样在术语表管辖内。

两侧共同遵守的口径：

- **只扫用户可见文案**：以 `//`、`/*`、`*`、`<!--` 开头的整行注释豁免——修复说明必须能点名旧词
  （如「已把『知识库体检』改为『体检中心』」），否则本表会自缚。
- **反向用例锁死有效性**：用例里断言「知识库文档 / 共享AI 写在文案行必须被抓到、写在注释里不抓」，
  防止禁用清单退化成空跑。
- **一致性断言**：菜单实名（`config/menu.ts`）与帮助条目名（`views/Help.vue`）同词；
  提示语「配置中心 → X」的 X 必须是 `configTabs.ts` 里存在的标签页实名（前后端两侧都验）。
- **豁免按侧生效**：`exempt` 的键是 `frontend` / `api`，前端的整文件豁免不会漏给后端。
- 新增术语冲突时：先改本表 → 再改 `terminology-bans.json` → 最后全站替换，不要只改一处文案。

三态口径另有两条可执行守护（T02476，同扫 `frontend/src` 全部 `.vue`）：

- `test/loading-empty-dialect.test.ts`：`<StateBlock>` 必须声明四态之一且真的被 import；
  `state="loading"` 必须带「正在………」场景文案；`state="empty"` 必须给主按钮或显式 `compact`
  （主从选择型空态进白名单，不许造假按钮）；退役方言类名（`.tree-empty`/`.content-loading`/
  `.progress-empty`/`.empty-dots` 等）与可见文案里的 ASCII `...` 一旦复活即失败；
  「加载中…」只允许出现在 `StateBlock.vue`。
- `test/state-block.test.ts`：锁组件契约（`role=status`/`aria-live`、骨架屏 vs 转圈、
  空态不渲染空 `.state-action`、失败态 `@retry` 恰好一次、`ready` 透传默认插槽）。
