## 1. 调研对象与结论

通过 GitHub MCP 检索并分析 3 个同类型知识库产品（均为 Karpathy LLM Wiki 模式的演进）：

| 仓库 | 定位 | 核心理念 |
| --- | --- | --- |
| `karpathy/llm-wiki` | LLM Wiki 原型 | 增量构建、结构化页面、双向链接 |
| `jasonxx/claude-obsidian`（社区同类） | 本地优先知识系统 | 来源溯源、合意知识循环（retain→ground→connect→use） |
| `eugeniughelbur/obsidian-second-brain` | AI 第二大脑 | 自维护 Agent、矛盾调和、OKM 事实时效分类 |

> 充分对齐本项目核心约束：**不引入向量库、不退化 compile 为查询时 RAG、不放弃结构化页面与双向链接、不依赖 Obsidian 专属插件**。以下所有优化均在这些约束内设计。

## 2. 本项目现状基线（V3.1 全量完成）

- 后端：22 路由模块 / 80+ API 端点；compile / query / health-check-fix 三工作流；session-lock 会话锁、compile-queue 队列、scheduler-manager 定时器
- 前端：16 视图 / 17 组件；问答核心（ThinkingBlock / RefsList / FollowupsChips / 多模态输入 / TTS）
- 知识图谱：Louvain 社区检测、4-signal 相关性、质量/性能双模式
- LLM 集成：两步链式摄取（分析→生成）、源引用列表、AI 自动打标签、实体抽取
- 验证基线：tsc + vue-tsc 0 报错，15 文件 / 294 测试 / 0 失败

## 3. 竞品优秀功能 → 本项目映射

| 竞品功能 | 来源仓库 | 本项目现状 | 差距 |
| --- | --- | --- | --- |
| 图洞察（surprising connections / knowledge gaps） | llm-wiki | Graph 已有 Louvain 社区 + 4-signal | ❌ 无"知识缺口 / 惊喜连接"分析 |
| 两步链式摄取（分析→生成） | llm-wiki | compile-workflow 已实现 | ✅ 已对齐 |
| 声明级溯源（authority / freshness / support / contradiction / confidence / review） | claude-obsidian | RefsList 已展示引用 | ⚠️ 仅"引用来源"，无"声明时效/置信/矛盾"状态 |
| 合意知识循环（capture→ground→connect→use） | claude-obsidian | 各环节独立存在 | ⚠️ 未串成可见闭环 UI |
| 并行 Agent 防竞争（worker 返回 draft、orchestrator 提交） | claude-obsidian | session-lock + compile-queue 已有 | ⚠️ 有机制无 review 合并策略 |
| 内容寻址不可变源副本 | claude-obsidian | raw/ 存源文件 | ⚠️ 无内容哈希去重标识 |
| 更新既有页面而非仅追加 | obsidian-second-brain | compile 追加页 | ⚠️ 默认追加，无主动 diff 更新模式 |
| 矛盾调和（contradiction reconciliation） | obsidian-second-brain | data-clean / diff-engine | ⚠️ 仅脏数据清洗，无"论证矛盾"调和 |
| OKM 事实时效（timeless / dated / pointer） | obsidian-second-brain | frontmatter 有 date 字段 | ⚠️ 无"过期事实"标记与执行策略 |
| auto-synthesis 自动综合 | obsidian-second-brain | 无 | ❌ 无单源多篇自动综合页 |
| scheduled maintenance agent | obsidian-second-brain | scheduler-manager 存在 | ⚠️ 仅数据清洗定时，无知识库自维护任务 |
| live research 实时检索 | obsidian-second-brain | web-search 已有 | ⚠️ 仅 web，无 RSS / 语料扩展 |

## 4. 可借鉴优化项明细

### 4.1 P0 —— 高价值低成本（可立即启动）

| # | 优化项 | 借鉴自 | 形态（对齐现有约束） |
| --- | --- | --- | --- |
| 1 | **知识缺口 / 孤岛检测** | llm-wiki | 基于现有 graph 拓扑，LLM 分析孤立节点、低密度子图，输出"你可能缺失的链接/主题"建议，仅建议不覆盖 |
| 2 | **声明时效标注** | obsidian-second-brain | 基于 frontmatter `date` 字段扩展时效状态（有效/需复核/过期），写入页面 frontmatter，compile 或 health-check 阶段填写 |
| 3 | **引用置信与复核状态** | claude-obsidian | RefsList 现有引用基础上补充 authority/confidence/review 三字段（源自 source 元数据），保持前端零安装 |

> P0 均基于现有数据与工作流，不引入新存储、不改变四大页面模板，改动集中在 compile / graph / RefsList。

### 4.2 P1 —— 中价值中成本（短期规划）

| # | 优化项 | 借鉴自 | 形态 |
| --- | --- | --- | --- |
| 4 | **合意知识循环闭环 UI** | claude-obsidian | Dashboard/Graph 增加"retain→ground→connect→use"流转状态可视化，让用户看到待处理源、已引用声明、探活频率 |
| 5 | **Review 合并策略（并行写防冲突）** | claude-obsidian | 现有的 session-lock + compile-queue 之上，显式化"worker 生成 draft → 单一 orchestrator 合并提交"，避免多 agent 写入竞态 |
| 6 | **周期性知识自维护任务** | obsidian-second-brain | 基于 scheduler-manager 增加"定期复检过期事实 / 悬空双链修复 / 孤立页提示"，对接现有 health-check-fix workflow |
| 7 | **更新既有页面（diff 合并模式）** | obsidian-second-brain | compile 配置项"新增 vs 更新"：命中同题页面时走 diff-engine 合并更新而非机械追加，可回退 |

### 4.3 P2 —— 中高价值高成本（中期）

| # | 优化项 | 借鉴自 | 形态 |
| --- | --- | --- | --- |
| 8 | **内容寻址源副本** | claude-obsidian | 摄入时对源文件计算内容哈希，作为去重/溯源标识写入 raw frontmatter，与现有 dedup-engine 协同 |
| 9 | **单源多篇自动综合** | obsidian-second-brain | 同一 source 多篇 note 自动生成综合/汇总页（新建指定 type 页面），**仅单源合并，不跨源 RAG** |
| 10 | **实时检索源扩展** | obsidian-second-brain | 在现有 web-search 之上扩展 RSS / 站点订阅导入，走 URL-ingest → compile 入库 |
| 11 | **方法论文页面结构** | claude-obsidian | 新增可选 page 模板标注"来自方法论/研究/观点"来源类别，前端 Browse 分组展示 |

### 4.4 明确拒绝项（与核心约束冲突或过度设计）

| 项 | 拒绝原因 |
| --- | --- |
| 独立向量库 / GraphRAG 隐式图 | 违反约束 6（禁止引入向量库）、约束 3（保留显式 `[[双链]]`） |
| 跨源 RAG / 查询时实时综合 | 违反约束 7（禁止跨源 RAG）、约束 1（compile 不退化查询时 RAG） |
| Obsidian Canvas / 原生插件依赖 | 违反约束 8（核心功能须 Web 零安装可用） |
| Agent Skills 多宿主 CLI 生态 | 与本项目"Web 桌面应用"场景不符，属过度设计 |

## 5. 与核心约束（V3.1 §6）对齐校验

| 约束 | P0~P2 是否触犯 | 说明 |
| --- | --- | --- |
| 1. compile 不退化查询时 RAG | ✅ 未触犯 | 所有生成/综合均在 compile 阶段落盘 |
| 2. 结构化页面输出 | ✅ 未触犯 | 时效/置信仅扩展 frontmatter，不新增页面类型 |
| 3. 双向链接图谱 | ✅ 未触犯 | 缺口检测仅基于 `[[双链]]` 拓扑，不引入隐式图 |
| 4. Harness 抽象 | ✅ 未触犯 | 自维护任务复用现有 health-check-fix workflow |
| 5. health-check-fix workflow | ✅ 未触犯 | 自维护事实复检并入该工作流 |
| 6. 禁独立 NER/向量库 | ✅ 未触犯 | 缺口头像/关联仍由 LLM 在 compile 阶段完成 |
| 7. 禁跨源 RAG | ✅ 未触犯 | 综合仅限单源，实时检索走 compile 入库 |
| 8. 禁 Obsidian 插件依赖 | ✅ 未触犯 | 全部在 Web 前端实现 |

## 6. 推荐实施顺序

1. **第一波（P0）**：#1 知识缺口检测 → #2 声明时效标注 → #3 引用置信复核
2. **第二波（P1）**：#4 合意闭环 UI → #5 review 合并策略 → #6 周期自维护 → #7 更新既有页面
3. **第三波（P2）**：#8 内容寻址 → #9 单源综合 → #10 实时检索扩展 → #11 方法论文结构
