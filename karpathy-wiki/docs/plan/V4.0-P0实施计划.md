## 1. 引言

### 1.1 编写目的

定义 V4.0 P0 三项（FR-17 知识缺口检测 / FR-18 知识时效标注 / FR-19 引用置信复核）的实施路径，作为开发执行的排期与跟踪依据。

### 1.2 实施原则

1. **依赖先行**：FR-18 → FR-19 共享 `knowledge_status` 信号与 refs 数据结构，先落地数据契约
2. **持续验证**：每阶段结束前通过 `tsc --noEmit` + 单测门禁
3. **增量交付**：FR-17 独立，可并行；每阶段产出可独立验证的功能切片
4. **不破坏 V3.1**：refs 双形态向后兼容、存量页面无 `knowledge_class` 兼容、字段改动不碰既有 frontmatter 字段
5. **PowerShell 适配**：所有命令用分号分隔，不用 `&&`
6. **编码约束**：新增 .vue/.ts 为 UTF-8 无 BOM；全部配置走 config.json，零硬编码；UI 颜色用 CSS 变量

### 1.3 环境与命令约定

- 操作系统：Windows 10；终端：PowerShell；包管理：pnpm
- 后端：`api/` 包 `@karpathy-wiki/api`；前端：`frontend/` 包 `@karpathy-wiki/web`
- 后端类型检查：`pnpm --filter @karpathy-wiki/api exec tsc --noEmit`
- 前端类型检查：`pnpm --filter @karpathy-wiki/web exec vue-tsc --noEmit`
- 单测：`pnpm --filter @karpathy-wiki/api test` / `pnpm --filter @karpathy-wiki/web test`
- 前端开发态启动：`pnpm --filter @karpathy-wiki/web dev`（Vite 5173）

## 3. 阶段一：基础设施与数据契约（S1）

### 3.1 目标

落地 V4.0 共享数据契约，为 FR-18 / FR-19 提供类型与配置基础。

### 3.2 任务拆解

| 任务 | 说明 | 涉及文件 | 验证 |
| --- | --- | --- | --- |
| T1-1 config 扩键 | 新增 `knowledge.freshnessStaleDays`（默认 365）、`graph.gapsMinPages`（默认 20）、`refs.authorityMap`（source 类别→等级映射）三个配置区间 | `api/src/config.ts` / `config.json` / `config.example.json` | 配置读取单测 |
| T1-2 前端枚举类型 | 定义 `KnowledgeClass`（timeless/dated/pointer）、`KnowledgeStatus`（ok/stale/unknown）、`RefSignal` 对象类型 | `api/src/types.ts` + 前端共享类型 | `tsc --noEmit` |
| T1-3 refs 双形态 | `refs: string[]` 升级为 `string \| RefSignalObject[]`，新增规范化函数 `normalizeRefs`（分辨 string 与对象，兼容映射） | `api/src/workflows/query-workflow.ts` / `types.ts` | 兼容映射单测 |
| T1-4 会话兼容 | `/api/conversations` 读写支持对象 refs，读旧会话 string→对象全 unknown 映射 | `api/src/routes/conversations.ts` | 旧会话读取单测 |

### 3.3 里程碑判定 M1

- 后端 `pnpm --filter @karpathy-wiki/api exec tsc --noEmit` 0 报错
- T1-3 / T1-4 兼容映射单测通过

## 4. 阶段二：FR-18 知识时效标注（后端）（S2）

### 4.1 目标

compile 生成页面落盘 `knowledge_class`，按确定性规则计算 `knowledge_status`，health-check 支持过期复检。

### 4.2 任务拆解

| 任务 | 说明 | 涉及文件 | 验证 |
| --- | --- | --- | --- |
| T2-1 compile prompt 扩字段 | `prompts/compile.md` 输出结构增加 `frontmatter.knowledge_class`（三值枚举），与 type 推断合并判定不新增请求 | `api/src/prompts/compile.md` / `compile-workflow.ts` | 输出结构 schema 校验 + 非法值回退 unknown |
| T2-2 status 判定规则 | 实现 `computeKnowledgeStatus(frontmatter)`：`dated` + `updated` 超 staleDays + 无 reviewed_at 或 reviewed_at 超 staleDays → stale；timeless/pointer→ok；无 class→unknown | `api/src/workflows/compile-workflow.ts` 或独立 `knowledge-status.ts` | 优先级链单测（含 reviewed_at 保质期） |
| T2-3 health-check 复检 | 扩展检查项：列出 stale 页面 + 批量追加 `reviewed_at: <ISO>`（不修改正文，追加后重算 status） | `api/src/workflows/health-check-fix-workflow.ts` + prompt | 复检单测（追加后 ok / 复核过期再 stale） |

### 4.3 里程碑判定 M2

- FR-18 单测覆盖：枚举校验/非法回退、stale 优先级链、reviewed_at 保质期、存量兼容
- `tsc --noEmit` 0 报错

## 10. 风险控制

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| compile prompt 修改导致既有字段漂移 | FR-18 依赖 | T6-4 结构回归前置，S2 即跑 |

| gaps 检测在超大图性能劣化 | FR-17 | 复用缓存图 O(V+E)，LLM 摘要截断（T4-1/T4-2） |
