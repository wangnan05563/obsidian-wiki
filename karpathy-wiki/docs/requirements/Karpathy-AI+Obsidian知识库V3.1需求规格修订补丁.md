## 2. P0 阻塞修正（4 项）

### 2.1 P0-1 修正：与 V2.2 §2.3 约束冲突的 4 项

#### 2.1.1 FR-13-1 重命名与路径澄清

**V3.0 原文**：
> FR-13-1：PDF 智能对话完整链路（P1）
> 借鉴来源：WPS PDF 对话 / RagFlow 深度解析
> AC-13-1：`Ingest.vue` 须支持 PDF 文件上传...

**V3.1 修订**：

| 字段 | V3.0 | V3.1 |
| --- | --- | --- |
| 需求名称 | PDF 智能对话完整链路 | **PDF 解析入库（走 compile 工作流）** |
| 借鉴来源 | WPS PDF 对话 / RagFlow 深度解析 | RagFlow 深度解析（仅借鉴解析能力，不借鉴对话路径） |
| 实现路径 | 模糊（PDF 对话 = RAG？） | **明确**：PDF 解析为 Markdown → 入 `raw/` → 走 compile 工作流编译为结构化页面 → 基于已编译页面问答 |
| 禁止路径 | 未声明 | **禁止**走"PDF 即时分块 + 向量检索 + LLM 问答"的 RAG 路径 |

**修订后的 AC-13-1**：
- AC-13-1：`Ingest.vue` 须支持 PDF 文件上传，解析后存入 `raw/papers/` 或 `raw/articles/`（按 frontmatter `type` 判定），**后续须走 compile 工作流编译**，不得跳过编译直接对 PDF 原文做 RAG 问答。

#### 2.1.2 FR-15-6 改为 LLM 在 compile 阶段抽取

**V3.0 原文**：
> AC-15-6：实体关系须由 NLP 抽取（如"张三是项目X的负责人"自动建立 Person→Project 的 `leader_of` 关系），存入 `.wiki/relations.json`。

**V3.1 修订**：

| 字段 | V3.0 | V3.1 |
| --- | --- | --- |
| 抽取方式 | NLP 抽取（暗示引入 NER 模型） | **由 LLM 在 compile 阶段抽取**（无独立 NER 模型，无向量库） |
| 存储方式 | `.wiki/relations.json` 独立文件 | **写入 frontmatter `entities` 字段 + `[[双向链接]]`** |
| 关系类型 | `author_of` / `participant_in` / `related_to` 等 | **保留**（关系类型不变，仅抽取主体改为 LLM） |

**修订后的 AC-15-6**：
- AC-15-6：实体关系须**由 LLM 在 compile 阶段抽取**（如"张三是项目X的负责人"自动建立 `[[张三]]` → `[[项目X]]` 的 `leader_of` 关系），抽取结果写入两篇笔记的 frontmatter `entities` 字段（如 `entities: [{name: "项目X", relation: "leader_of"}]`）+ 笔记正文 `[[双向链接]]`，**不得引入独立 NER 模型或向量库**。

#### 2.1.3 FR-16-2 降级 P3 并限定 ingest 用途

**V3.0 原文**：
> FR-16-2：联邦搜索（P3）
> AC-16-4：`Query.vue` 须提供"联邦搜索"开关（默认关闭），开启后可检索外部数据源。

**V3.1 修订**：

| 字段 | V3.0 | V3.1 |
| --- | --- | --- |
| 优先级 | P3 | **P3（v0.5 长期方向）** |
| 用途 | 联邦搜索（跨源 RAG） | **仅用于 ingest**（外部源须先 compile 入库，再走 LLM Wiki 问答） |
| 禁止 | 未声明 | **禁止**跨源 RAG（外部源不得跳过 compile 直接参与运行时问答） |

**修订后的 AC-16-4 ~ AC-16-7**：
- AC-16-4：`Ingest.vue` 须提供"外部源 Connector"入口（非 Query.vue），配置 GitHub repo / 本地文件夹路径 / 浏览器书签导出文件，元数据缓存至 `.wiki/connectors/`。
- AC-16-5：外部源 Connector **仅用于将外部内容抓取到 `raw/` 目录**，后续须走 compile 工作流编译为结构化页面，**不得跳过编译直接参与运行时问答**。
- AC-16-6：联邦搜索**移除**——本项目不走跨源 RAG 路径，外部源内容须先 compile 入库再走 LLM Wiki 问答。
- AC-16-7：外部源结果须标注"外部"标识与源类型，跳转时打开外部链接（如 GitHub commit URL）。

#### 2.1.4 FR-13-3 音视频转写降级 P3

**V3.0 原文**：
> FR-13-3：音频/视频转写入库（P2）

**V3.1 修订**：

| 字段 | V3.0 | V3.1 |
| --- | --- | --- |
| 优先级 | P2 | **P3（v0.5 长期方向）** |

### 2.3 P0-3 修正：FR-12 Skill Adapter 改为扩展 EngineAdapter

**V3.0 原文**：
> FR-12：AI 伙伴预设（Skill Adapter = 模型+范围+系统提示词+工具集）
> AC-12-1：须提供"AI 伙伴管理"页（`Config.vue` 扩展）...
> AC-12-3：AI 伙伴定义须保存为 Markdown 文件（`skills/{name}.md`）...
> AC-12-5：AI 伙伴的引用范围须严格执行——若范围限定为 `folder: concepts/`，问答时不得检索其他目录。

**V3.1 修订**：

| 字段 | V3.0 | V3.1 |
| --- | --- | --- |
| 需求名称 | AI 伙伴预设（Skill Adapter） | **AI 伙伴预设（扩展 EngineAdapter.updateConfig）** |
| 实现路径 | 新增 SkillAdapter 接口 + Markdown 定义文件 | **扩展 EngineAdapter.updateConfig 参数**（不新增接口） |
| 存储方式 | Markdown 文件（`skills/{name}.md`） | **config.json 的 `skills` 数组**（避免引入新文件类型） |
| 范围限定 | 重构 query 工作流检索逻辑 | **在 query 工作流的 search 工具中传入 `scopeFilter` 参数**（不重构工作流） |
| 优先级 | P1 | **P2（v0.5 长期方向）** |

**修订后的 FR-12 验收标准**：

- AC-12-1：须提供"AI 伙伴管理"页（`Config.vue` 扩展），支持创建/编辑/删除/复制 AI 伙伴。
- AC-12-2：每个 AI 伙伴须可配置：LLM 模型、引用范围（tag/folder/all）、system prompt、输出格式（问答/摘要/播客脚本等）、工具集（compile/query/web_search 等子集）。
- AC-12-3：AI 伙伴定义须保存为 **config.json 的 `skills` 数组项**（不引入新的 Markdown 文件类型与解析逻辑），结构示例：
  ```json
  {
    "skills": [
      {
        "name": "文献综述",
        "model": "deepseek-chat",
        "scope": { "type": "folder", "value": "concepts/" },
        "systemPrompt": "...",
        "outputFormat": "summary",
        "tools": ["query", "web_search"]
      }
    ]
  }
  ```
- AC-12-4：`Query.vue` 须支持"当前 AI 伙伴"切换器，切换后调用 `engineAdapter.updateConfig({ model, scope, systemPrompt, tools })` 即时生效（**复用现有 updateConfig 机制，不新增接口**）。
- AC-12-5：AI 伙伴的引用范围须在 **query 工作流的 search 工具中传入 `scopeFilter` 参数**实现（如范围限定为 `folder: concepts/`，search 工具仅检索 concepts/ 目录），**不重构 query 工作流主体逻辑**。
- AC-12-6：须提供至少 3 个内置 AI 伙伴模板：通用问答 / 文献综述 / 学习卡片生成。
- AC-12-7：AI 伙伴须支持"导入/导出"为 `.skill.json` 文件，便于跨 Vault 共享。

8. **禁止依赖 Obsidian 专属插件作为核心功能**——所有核心功能须在 Web 前端零安装环境下可用，Obsidian 插件（如 Templater / Dataview）仅作为可选增强，不得作为需求验收的必要条件（坚守 V2.2 NFR-05 "15 分钟搭建 + 零命令行日常使用"）。
