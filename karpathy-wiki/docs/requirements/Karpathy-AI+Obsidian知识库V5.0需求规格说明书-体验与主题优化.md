## 1. 引言

### 1.1 背景

T01718 完成 16 个 GitHub 同款知识库产品的调研（Obsidian/Logseq/SiYuan/Joplin/TriliumNext/Khoj/Reor/AnythingLLM/Cherry Studio/Open WebUI/LobeChat/AFFiNE/AppFlowy/Outline/Docmost/Anytype），产出 A 体验 / B 功能 / C UI / D 主题四维度 24 项优化需求清单。T01721 评审结论：P0 五项通过并形成本 SRS；P1/P2 缓议（理由见 §1.2）。五项均为「高价值 + 可复用现有地基（流式续传 / BYOK 多模型 / SQLite / CSS 变量）」项，不引入独立向量库服务、不改变 vault 存储模型。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 混合检索 | 关键词检索（SQLite FTS5，BM25 排序）与向量语义检索双路召回，经 RRF（Reciprocal Rank Fusion）融合排序的检索方式 |
| chunk | 文档切分后的检索最小单元，带（页面 id，偏移/块定位）坐标，是引用溯源的锚点 |
| RRF | `score = Σ 1/(k + rank_i)`（k=60 常量），无需调权重的双路融合公式 |
| 引用溯源 | AI 回答中的内联编号 `[n]`，可展开查看被引 chunk 原文并高亮，点击可跳转源页面 |
| 思考过程 | 推理型模型在正式回答前输出的 `<think>…</think>`（或等价 reasoning）内容 |
| 主题 token | 语义分层的 CSS 变量：base（页面底色）/ surface（卡片、面板）/ accent（强调、激活态）/ text（文字层级），主题 = 一组 token 值 |
| 暗色模式 | 全站（含移动端）一键切换的深色主题，token 值整体替换，不逐组件硬编码 |

### 1.4 与现有子系统的边界声明

| 现有子系统 | 边界 |
| --- | --- |
| V4.0 FR-19 引用置信（authority / confidence / review 信号） | FR-21 是引用的**呈现与跳转 UI**，FR-19 是引用的**置信信号**。FR-21 的引用浮层可展示 FR-19 信号作为辅助信息，但不实现、不重复计算置信度；FR-19 未交付的部分不受本 SRS 影响 |
| CODING-STREAMING-RESUME（流式断点续传） | FR-22 的「取消」是新增的用户主动中断语义（区别于断线自动续传）；续传机制本身不改动，取消后该轮会话进入「已中断」终态，不自动续传 |
| CODING-BYOK（缺密钥 400 不回落） | FR-20 的 embedding 调用同样走 BYOK：未配置 embedding key 时语义检索降级为纯关键词检索并提示，**不回落到任何默认 key** |
| 主题体系（默认 / macaron / ecommerce + `--menu-active-fg`） | FR-24 是**重构而非新建**：现有三主题迁移为 token 值组合；「浅色背景激活态必须覆盖 `--menu-active-fg`」教训升级为 token 体系硬规则（§5 NFR-2） |
| SQLite 池化（AsyncAdaptedQueuePool 20+100） | FR-20 的向量表与 FTS5 表建在同一 SQLite 库内（**不引入独立向量库**，约束 6 合规）；向量写入走现有池，上限维持「覆盖等写锁期持连接峰值」的既有结论 |
| 移动端 MobileShell（M0–M5） | FR-22 / FR-23 / FR-24 须同步覆盖移动端（复用 MobileQuery / MobileListen 现有页面，不另起炉灶） |

## 2. 约束（继承 V3.1 §6，8 项全部有效）

本 SRS 全部需求在以下约束内设计：

1. 不退化 compile 为查询时 RAG —— FR-20 是**查询时检索增强**，不触碰 compile 产物
2. 不放弃结构化页面输出（vault 四类页面模板）
3. 不放弃双向链接图谱（不用隐式图替代显式 `[[链接]]`）
4. 不放弃 Harness 抽象
5. 不放弃 health-check-fix workflow
6. **禁止引入独立 NER 模型或向量库** —— FR-20 合规适配：向量以 BLOB 存于同一 SQLite 库，embedding 计算**外置**到用户 BYOK 的 embedding API（无本地模型、无独立向量库进程）
7. 禁止跨源 RAG —— FR-20 / FR-21 检索与引用范围仅限本库内页面
8. 禁止依赖 Obsidian 专属插件（核心功能须 Web 零安装可用）

## 3. 功能需求

### FR-20 语义搜索（混合检索）

**描述**：搜索框升级为混合检索——关键词（FTS5 BM25）+ 向量语义双路召回、RRF 融合排序；结果并入现有搜索/浏览入口。

**用户故事**：作为用户，我用自然语言（如「关于流式断点续传的设计」）搜索，即使页面中没有逐字匹配的关键词，也能命中语义相关的页面。

**功能规格**：

1. 摄取/编辑页面时异步切分 chunk（目标 300–500 字，重叠 50 字），调用 BYOK embedding API 生成向量，与 chunk 文本、页面 id、定位信息一并写入 SQLite（新表 `chunks` + `chunk_vecs`）；失败重试 ≤3 次后标记该页面「索引待补」，不阻塞摄取主流程
2. 未配置 embedding key（BYOK 400 语义）：语义路自动关闭，仅关键词路生效，搜索框展示「语义检索未启用」轻提示
3. 查询时：双路各取 top-20 → RRF（k=60）融合 → top-10 返回；结果项含页面标题、命中摘要、来源路（关键词/语义/双命中）
4. 索引重建入口（设置页），显示已索引/待补页面数
5. 前端搜索结果复用现有列表样式，语义命中项加可区分标识

**验收标准**：

- [ ] 删除停用词场景：查询与页面无逐字重叠词时，语义路可召回该页面 top-5
- [ ] BYOK 缺 embedding key 时仅关键词路可用且无报错、无回落
- [ ] 1000 chunk 量级单次查询 P95 < 800ms（本地机）
- [ ] 摄取期间索引失败不阻塞页面保存；重建索引后待补清零

### FR-21 AI 引用溯源

**描述**：AI 回答基于检索结果作答时，内联引用编号 `[n]`；编号可展开浮层显示被引 chunk 原文（高亮命中段），并提供跳转源页面链接。

**用户故事**：作为用户，我看到回答中的 `[1]` 悬停/点击后能立刻看到原文依据并一键跳转，判断答案可信度。

**功能规格**：

1. 问答链路检索层返回 chunk 坐标（页面 id + 定位）；LLM 提示词要求引用使用 `[n]` 编号，n 对应本次检索结果槽位
2. 前端渲染层把 `[n]` 解析为角标组件（未匹配到槽位的 `[n]` 按普通文本保留，不渲染角标）
3. 引用浮层：chunk 原文 + 命中段高亮 + 页面标题/路径 + 「打开页面」；浮层复用 `AppModal`/popover 规范，不做第二套样式
4. 移动端：浮层改为底部抽屉（`variant="drawer"`，不加 `append-to-body`，遵循既有测试 DOM 约定）
5. 回答中的引用列表折叠置于回答尾部（默认收起，展示「N 个来源」）

**验收标准**：

- [ ] 含引用的回答中所有合法 `[n]` 均可展开浮层并跳转正确页面
- [ ] 无检索结果的会话（纯对话）不出现引用区
- [ ] 流式过程中角标随文本增量渲染，续传恢复后编号不错位
- [ ] 桌面 + 移动端均通过既有 UI 守卫（IconActionButton/data-tip 规范）

### FR-22 问答稳健性（取消 / 失败停止重试 / 历史持久化）

**描述**：补齐 AI 问答三项稳健性语义：用户主动取消；失败后不自动重试（由用户决定）；会话历史本地持久化，刷新/重启不丢。

**用户故事**：作为用户，我发出错误提问后能立即停止生成；网络失败时不会被自动重试刷屏；关掉应用再打开，历史会话还在。

**功能规格**：

1. 「停止」按钮（IconActionButton，aria-label `停止生成 - 中断当前回答`）：前端 AbortController + 后端请求终止；已生成部分保留并标记「已中断」终态，**不**触发自动续传、不自动重试
2. 请求失败（网络/超时/400）：展示一次性错误态与「重试」按钮；同一轮失败不做后台自动重试（BYOK 400 缺密钥按 CODING-BYOK 直接呈现配置引导，不回落）
3. 会话历史持久化沿用现有 IndexedDB 存储；`dbPut` 前必须 `JSON.parse(JSON.stringify(x))` 深拷贝剥离 Vue/Pinia 代理（CODING-IDB-REACTIVE-CLONE）
4. 「已中断 / 已失败」终态在历史列表中有明确视觉区分，且重新进入会话后不再尝试续传

**验收标准**：

- [ ] 停止后 ≤1s 内前端停止渲染、后端上游连接终止（服务端日志可证）
- [ ] 制造 500/断网：仅出现一次错误态 + 手动重试按钮，无自动重试请求
- [ ] 刷新页面 / 重启应用后历史会话完整可回看，中断会话状态正确
- [ ] 移动端 MobileQuery 同样具备停止与重试入口

### FR-23 思考过程折叠渲染

**描述**：推理型模型输出的 `<think>…</think>`（含流式半开标签）解析为可折叠面板，默认收起；不影响正式回答的 Markdown 渲染。

**用户故事**：作为用户，我能默认看到干净的答案，需要时展开查看模型推理过程。

**功能规格**：

1. 流式解析器增量识别 `<think>` / `</think>`：半开标签期间内容进入 thinking 缓冲，闭合后进入回答缓冲；两种状态可随时切换
2. 折叠面板置于回答顶部：标题「思考过程（N 字）」，展开/收起状态记忆到会话级偏好
3. thinking 内容按纯文本+换行渲染（不做 Markdown 重排），回答内容走现有渲染管线
4. 无思考输出的模型不渲染该面板
5. 断点续传恢复后 thinking/回答分区不错位（与 CODING-STREAMING-RESUME 对齐）

**验收标准**：

- [ ] 含 `<think>` 的流式回答：面板出现且答案区不含 think 原文；非流式（一次性返回）同样正确
- [ ] 半开标签截断场景（连接中断）：已缓冲思考内容不丢失、不错渲染进答案
- [ ] 无 think 输出时面板零渲染

### FR-24 CSS 变量主题架构 + 暗色模式

**描述**：建立语义分层主题 token 体系（base/surface/accent/text），现有三主题（默认/macaron/ecommerce）迁移为 token 组合；新增全站暗色模式（含移动端），一键切换、实时生效、无需刷新。

**用户故事**：作为用户，我在设置中一键切换明暗主题，所有页面（含弹窗、菜单、移动端）立即整体变色，无错色、无不可读文字。

**功能规格**：

1. 新建 `frontend/src/styles/tokens.css`：定义 `--tk-base / --tk-surface / --tk-surface-2 / --tk-accent / --tk-accent-fg / --tk-text / --tk-text-2 / --tk-border` 等语义变量；`:root` 为浅色默认，`[data-theme="dark"]` 整体覆盖
2. 现有三主题迁移：主题 = 浅色 token 集 +（可选）激活态覆盖；`--menu-active-fg` 纳入 accent-fg 体系（旧变量名保留别名，避免一次性断裂）
3. 硬性规则（防复发「白图标不可见」坑）：任何主题的**浅色/深色激活背景都必须同步声明 accent-fg**，缺省时构建期校验（脚本 grep token 定义完整性）报错
4. 主题切换：写入用户偏好（IndexedDB），`documentElement.dataset.theme` 即时切换；全站组件颜色只允许消费 token，新增硬编码色值由 code review 门禁拦截
5. 暗色模式覆盖范围：桌面全部页面 + AppModal（dialog/drawer 两形态）+ 移动端五 Tab（mobile-light.css 增加 dark 变体）；Element Plus 组件走 `--el-*` 变量桥接到 token
6. 移动端视觉基准不变：暗色不是「深蓝商务」，为浅白极简风的等价深色版（bg 近黑、text 近白、accent 沿用深蓝系）

**验收标准**：

- [ ] 明/暗切换全站无刷新生效；弹窗、抽屉、菜单选中态、代码块、mermaid 图文字可读
- [ ] 现有三主题在明/暗下均通过「激活态文字可见」检查（token 校验脚本通过）
- [ ] 现有测试全绿；新增 token 完整性校验接入构建门禁
- [ ] 移动端五 Tab 暗色下无硬编码白底残留（grep `#fff`/`#111` 于组件内为零）

## 6. 测试计划

1. **单元/组件**：FR-23 流式解析器（半开标签、续传恢复、无 think）；FR-21 角标解析（合法/非法 `[n]`）；FR-24 token 完整性校验脚本
