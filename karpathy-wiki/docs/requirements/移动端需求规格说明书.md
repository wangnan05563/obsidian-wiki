## 1. 引言

### 1.1 目的
为 `karpathy-wiki` 增加**移动端（手机）**访问能力，定义移动端的信息架构、各页面功能需求、非功能需求、接口复用方案与实施计划，作为后续移动端前端开发（Vue 组件 + 响应式 `MobileShell`）的输入依据。

### 1.2 背景
现有前端是**桌面优先**的单页管理后台（Vue 3 + Element Plus + Pinia），采用左侧可折叠侧边栏导航，共 16 个菜单项，**零响应式 CSS**。已具备 `viewport` meta 与 PWA `manifest.webmanifest`。

产品核心闭环：**投递资料 → AI 编译 → 结构化页面 → 知识问答**。
移动端应聚焦"手机高频场景"，做桌面端的轻便延伸，而非搬运全部管理功能。

### 1.3 范围
- **包含（本期）**：移动端登录/注册、知识问答（AI 对话）、知识浏览（读笔记/文章）、聆听（TTS 语音播放）、投递采集（链接/文件/文字/拍照）、我的（账户与 BYOK/TTS 设置）。
- **不包含（本期）**：图谱可视化编辑、系统清理、内网穿透、用户管理后台、数据清洗等重管理功能（移动端本期不提供入口，或仅保留只读概览于后续版本）。
- **交付形态**：本期交付**需求规格说明书 + 可交互 HTML 高保真原型**；实际 Vue 代码实现列为后续里程碑（见 §8）。

### 1.4 术语
- **SPA**：单页应用；**SSE**：Server-Sent Events 服务端流式推送。
- **BYOK**：Bring Your Own Key，每用户自带 LLM API 密钥（本项目问答强制）。
- **Vault**：Obsidian 同步文件夹，是本系统的唯一知识内容源。
- **TTS**：文本转语音（Text-To-Speech）。
- **MobileShell**：本期拟新增的移动端容器组件，承载底部 Tab 导航。

## 2. 总体描述

### 2.1 产品视角
移动端是桌面端的"轻便延伸"，**共享同一后端、同一套鉴权/会话/数据模型**。用户在手机上完成：随手提问、碎片阅读、通勤聆听、随手采集。重编排、重管理仍回到桌面完成。

### 2.2 用户角色
| 角色 | 说明 | 移动端权限 |
|---|---|---|
| 游客 guest | 未登录 | 仅可访问登录页 |
| 普通用户 user | 注册即用户（role=user） | 登录后可用全部移动功能；BYOK 密钥自行配置 |
| 管理员 admin | 由管理员创建 | 额外可查看只读概览（仪表盘精简版，可选） |

### 2.3 运行环境
- 移动浏览器：iOS Safari 15+、Android Chrome 90+；支持 PWA「添加到主屏幕」。
- 视口：适配 **320–430px** 宽度（主流手机）；平板 ≥768px 优雅降级或回退桌面布局（见 R4/O1）。
- 网络：依赖后端 `/wiki/api`（同源或经 Tailscale Funnel 暴露）。

### 2.4 设计与实现约束
- **单 SPA、无 vue-router**：沿用 `App.vue` 的 `currentView` 机制，新增 `isMobile` 判定（`matchMedia` + 手动覆盖），渲染 `MobileShell.vue` 替代桌面侧边栏；**不引入路由库**。
- **最大化复用**：全部沿用现有 `stores/`（auth、conversations、query、tts、model…）、`services/`（apiFetch、chatDb、userConfig、ttsConfig）、`utils/sse.consumeQuerySSE`、`components/`（ThinkingBlock、RefsList、MultimodalOutputCard、MessageToolbar、FollowupsChips、MarkdownRenderer）。
- **构建管线不变**：仍 `vite build` → `api/public`，Fastify `@fastify/static` 单端口伺服；SPA fallback 已支持任意前端路径，新增移动视图无需改后端路由。
- **会话默认仅客户端**：IndexedDB `karpathy-wiki-chat`，`ownerId` 隔离 + 可选信封加密，不依赖服务端持久化（默认 `conversationsPersist=false`）。

### 2.5 假设与依赖
- 后端 `POST /api/query` **强制 BYOK**：移动端必须提供每用户 `apiKey`，否则问答返回 400（需在「我的 → API Key」引导配置）。
- TTS 走 `POST /api/tts/synthesize`（Edge 合成 MP3），后端不可达自动降级浏览器原生 TTS。
- Obsidian 即 Vault 文件源，**无独立「Obsidian 投递」接口**；移动端「投递」复用 `/api/compile`（文件 / URL / 文本）。

## 3. 移动端信息架构

### 3.1 导航模型
- **未登录**：全屏登录/注册页（无导航栏）。
- **已登录**：**底部 Tab 导航（5 个）**，替代桌面侧边栏。每个 Tab 对应一个移动视图；视图内二级页（笔记详情、对话历史、设置子页）以「页内下钻 + 返回」或**底部弹层（bottom sheet）**呈现。
- 底部 Tab 顺序：`问答` · `浏览` · `聆听` · `投递` · `我的`。
- 顶部 App Bar 随页面变化（标题 + 次要操作）。

### 3.2 页面结构与导航流

```mermaid
flowchart TD
    A[登录 / 注册] -->|成功后| H[移动主页：底部 Tab]
    H --> Q[问答\n对话历史 sheet\n会话详情]
    H --> B[浏览\n笔记详情 reader]
    H --> L[聆听\n正在播放\n播放列表]
    H --> I[投递\n采集表单 链接|文件|文字|拍照\n进度 sheet\n结果]
    H --> M[我的\nAPI Key 设置\nTTS 设置\n主题 / 账户 / 关于]
    B -.朗读此篇.-> L
    Q -.加入聆听.-> L
```

### 3.3 与桌面端关系
- 共享后端、鉴权、会话（IndexedDB `ownerId` 隔离）、数据模型与权限点（`AuthPermission`）。
- 移动端「我的」内嵌**浓缩版配置**（仅 BYOK、TTS、主题），不搬运桌面 `Config.vue` 全部项。
- 桌面端已有的 FloatingChat / Query / Browse / Ingest 逻辑通过 composable 复用，避免重复实现问答流与浏览流。

## 4. 功能需求

### 4.1 登录与注册（M-AUTH）
- **FR-AUTH-01** 登录表单：用户名、密码、登录按钮；调用 `POST /api/auth/login`。成功后存 `token`（localStorage）、`user`（内存），进入移动主页默认 Tab = 问答。
- **FR-AUTH-02** 注册入口（默认角色 user）：`POST /api/auth/register`，注册即登录。
- **FR-AUTH-03** 登录失败（401 / 网络）显示内联错误，不跳转、不丢输入。
- **FR-AUTH-04** 启动恢复会话：`GET /api/auth/me` 校验 token；有效则跳过登录直达主页；无效则登录页。
- **FR-AUTH-05** 「记住登录」默认开（token 持久化）；登出清 token + 作废当前会话作用域（`resetSession`），IndexedDB 会话保留待同账户恢复。
- **FR-AUTH-06** 登录页含品牌 Logo、BYOK 安全提示；输入框/按钮触控目标 ≥44px。

### 4.2 知识问答（M-QUERY）— 核心场景
- **FR-QRY-01** 消息列表：用户气泡右对齐、助手左对齐；渲染 Markdown（`MarkdownRenderer`）、思考块（`ThinkingBlock`，默认折叠可展开）、多模态卡片（`MultimodalOutputCard`：mindmap/faq/timeline/image/ppt）、引用（`RefsList`：vault 内部链接 + web 外链）、追问 chips（`FollowupsChips`：点击填入输入框）、消息工具条（`MessageToolbar`：复制/朗读/重生成/反馈/删除/归档）。
- **FR-QRY-02** 流式问答：复用 `consumeQuerySSE` 消费 `POST /api/query`；首字节前显示加载点；实时追加 `answer`；`done` 后落盘（`persistConversation`）+ 断点续答（FR-RM-09）。
- **FR-QRY-03** 输入区：自适应高度文本框、附件按钮（图片/文件，作为 query `attachments`）、模式切换（联网 `web` / 深度 `deep`）、发送/停止按钮（流式时可停止为 `interrupted`）。
- **FR-QRY-04** 会话管理：Tab 内「新对话」按钮；对话历史以**底部弹层**列出（置顶优先，简化重命名/置顶/删除）；切换会话加载对应 `messages`。
- **FR-QRY-05** BYOK 缺失兜底：发送时若未配置 `apiKey`，后端 400；前端拦截并在输入区上方提示「未配置 API Key，去『我的』配置」并提供跳转入口。
- **FR-QRY-06** 消息级朗读：复用 TTS（edge provider → `/api/tts/synthesize`）朗读单条助手消息；朗读时底部浮现迷你控制器（复用 `TtsController`）；「加入聆听」将本条加入聆听播放列表。
- **FR-QRY-07** 自动滚动贴底（`useChatAutoScroll`）；长对话分页/虚拟滚动（后续），首期渲染最近 N 条。

### 4.3 知识浏览（M-BROWSE）
- **FR-BRW-01** 顶部搜索框：输入即调 `GET /api/search?q=`，展示命中卡片（标题、目录徽标、snippet、命中数）。
- **FR-BRW-02** 推荐/最近：调 `GET /api/files/pages`，按 `dir` 分组或按 frontmatter 时间排序，展示「最近更新/推荐」列表（可选接入 `GET /api/stats` 概览）。
- **FR-BRW-03** 条目详情（reader）：点卡片 → 下钻页，`GET /api/files?path=` 取 `body`，`MarkdownRenderer` 渲染正文；顶部返回；底部「朗读此篇」按钮（加入聆听）。
- **FR-BRW-04** 下拉刷新；列表分页/无限滚动（按 `total` 加载更多）。
- **FR-BRW-05**（可选）标签/目录筛选：基于 frontmatter 过滤。

### 4.4 聆听（M-LISTEN）— TTS 播放器
- **FR-LIS-01** **播放列表模型**（扩展现有单条朗读）：维护队列（条目或选定文本片段）；数据源：浏览「朗读此篇」、问答「加入聆听」、手动添加。
- **FR-LIS-02** 正在播放卡片：标题、进度条（可拖动）、播放/暂停、上一首/下一首、倍速（0.75–2.0×）、音色选择（`GET /api/tts/voices`）。
- **FR-LIS-03** 合成与播放：逐条调 `/api/tts/synthesize` 获取 MP3（长文本分段，`>2000` 字切片），`HTMLAudioElement` 播放；后端不可达降级浏览器 TTS。
- **FR-LIS-04**（增强项）后台播放：集成 **Media Session API**（锁屏控制/封面/标题）；PWA + Service Worker 缓存音频实现离线（后续里程碑）。
- **FR-LIS-05** 设置持久化：语速/音色/风格/provider 写入 `tts-config::<userId>`（IndexedDB），与桌面 TTS 设置互通。
- **FR-LIS-06** 播放进度/当前项高亮；清空队列、删除单项。

### 4.5 投递采集（M-INGEST）
- **FR-ING-01** 四种采集入口（分段控件）：
  - **链接**：粘贴 URL → `POST /api/compile {type:'url', content}`；
  - **文件**：从手机选择文档（md/txt/pdf/html/json/docx/xlsx/pptx/doc/xls）→ multipart `/api/compile`；
  - **文字**：粘贴文本 → `{type:'text', content}`；
  - **拍照**：调用相机/相册取图 → 作为视觉上下文，提交为「以图问库」草稿（附带图片 `attachment` 的 query，或由 LLM 转写摘要后归档入 Vault）。**若无 OCR 端点，拍照采集走「视觉问答 → 归档」路径，不直接入库图片**（见 R2）。
- **FR-ING-02** 提交后 SSE 进度弹层：展示 `progress` / `page` / `done` / `error`；`done` 显示生成页面标题与「查看」跳转 Browse 详情。
- **FR-ING-03** 最近采集列表（本地记录 path/title/time）；失败可重试。
- **FR-ING-04** 输入校验：空内容禁用提交；文件类型/大小前端预检（超 `maxFileSizeMb` 提示）。

### 4.6 我的（M-ME）
- **FR-ME-01** 账户信息卡：用户名、角色（徽标）；登出按钮（FR-AUTH-05 逻辑）。
- **FR-ME-02** **API Key 设置（BYOK）**：provider/baseUrl/model/apiKey 录入（密码框、本地存于 `userConfig`，请求时携带于 `llmConfig`）；显示「已配置/未配置」状态与去问答引导。
- **FR-ME-03** TTS 设置：provider（edge/browser）、voice、style、rate、volume、pitch（与 FR-LIS-05 同一配置）。
- **FR-ME-04** 主题：浅色/深色（复用 `ThemeSwitcher` 逻辑，写本地偏好）。
- **FR-ME-05** 关于：版本、仓库说明、BYOK 与隐私说明。
- **FR-ME-06**（可选）精简仪表盘入口：只读 `GET /api/stats` 概览（总页数、链接数、分类计数）。

## 5. 非功能需求

### 5.1 性能
- 首屏（登录后到可交互）移动网络 < 3s（建议对移动视图做代码分割）。
- 问答流式首字节渲染 < 500ms（网络正常）；列表滚动 60fps。
- 图片/音频懒加载；长会话/长列表虚拟滚动。

### 5.2 响应式与适配
- 断点：**<768px** 启用移动布局（MobileShell + 底部 Tab）；**≥768px** 保留/回退桌面侧边栏（或平板适配布局，见 O1）。
- 触控目标 ≥44×44px；正文字号 ≥14px；间距遵循 8dp 栅格。
- 适配刘海/灵动岛：安全区 `env(safe-area-inset-*)`；底部 Tab 避开 Home Indicator。

### 5.3 可访问性
- 语义化标签、可聚焦、`aria-label`；颜色对比度达标（WCAG AA）；支持系统字体缩放；`prefers-reduced-motion` 降级动效。

### 5.4 安全与隐私
- 沿用现有：token 仅 localStorage、HTTPS 传输；BYOK `apiKey` 不落服务端（`/api/query` 仅请求体携带，符合 CODING-BYOK）。
- 多账户隔离沿用 `ownerId` + `resetSession`，防跨账户会话泄漏。
- 移动端不展示服务端敏感配置（apiKeyMasked 模式）。
- 登出作废作用域；IndexedDB 可选加密（FR-RM-07）在登录时 `unlockVault`。

### 5.5 离线
- 已会话/已浏览内容缓存于 IndexedDB，弱网可回顾；TTS 音频可缓存（后续 SW）。
- 提交类操作（问答/投递）需联网，离线给出明确提示。

### 5.6 兼容性
- iOS Safari 15+、Android Chrome 90+；PWA 安装（`manifest` 已存在，补充 icons/start_url 适配移动）。

## 7. 验收标准（摘录）
- 手机 Safari/Chrome 打开登录页布局**无横向滚动**；登录后底部 5 Tab 可切换且各自内容正确渲染。
- **问答**：输入问题 → 流式输出 → 引用/追问可交互 → 停止/重生成可用；无 apiKey 时给出配置引导且不崩溃。
- **浏览**：搜索返回结果卡片；点开详情可阅读 Markdown 正文；「朗读此篇」可加入聆听。
- **聆听**：播放/暂停/倍速/切首可用；Media Session 锁屏可控（增强项）。
- **投递**：链接/文字提交后进度弹层 → `done` 可查看生成页；拍照入口在 iOS/Android 可唤起相机。
- **我的**：配置 apiKey 后问答不再 400；TTS 设置变更即时生效；登出回到登录页且会话隔离。

## 8. 实施计划（里程碑建议）
- **M0 脚手架**：`isMobile` 判定 + `MobileShell` + 底部 Tab 切换（`currentView` 扩展）；复用样式变量。（1–2 天）
- **M1 登录/我的**（BYOK/TTS/主题）+ 会话恢复。（2–3 天）
- **M2 问答移动视图**（复用 query 流 + 移动聊天 UI + 历史 sheet）。（3–5 天）
- **M3 浏览移动视图**（搜索/详情/朗读入口）。（2–3 天）
- **M4 投递移动视图**（链接/文字/文件/拍照 + 进度）。（3–4 天）
- **M5 聆听播放列表 + Media Session + SW 离线**（增强）。（3–5 天）
- **M6 回归**：响应式回归矩阵（320/375/414/768）、会话隔离回归、BYOK 400 兜底回归、性能预算。

## 9. 风险与开放问题
- **R1** 后台播放需 Service Worker + 媒体会话，iOS 限制较多，列为增强项。
- **R2** 拍照直接入库缺 OCR 端点，暂以「视觉问答 → 归档」路径实现，需确认产品预期。
- **R3** BYOK 强制：未配置密钥手机端问答不可用，需在首次进入即引导配置，避免空体验。
- **R4** 桌面侧边栏与移动底部 Tab 共存：需明确断点策略与大屏回退，避免布局冲突。
- **R5** 现有 `ChatMessage.refs` 为 `string[] | Reference[]` 混合，移动端渲染需统一归一化。
- **O1** Tablet ≥768px 提供「桌面布局」还是「放大移动布局」？建议回退桌面。
- **O2** 管理员移动端是否需要完整用户管理？建议本期仅只读概览。
