## 1. 引言

### 1.1 编写目的

本文档定义 Karpathy AI + Obsidian 知识库在「用户注册」与「多用户数据隔离」两个维度上的需求规格，作为后续完善注册模块、实现本地化会话存储的工程输入基线。文档面向：

- **开发人员**：作为注册接口、前端注册页、会话本地化改造的实施依据；
- **测试人员**：作为验收用例（§8）的来源；
- **产品经理 / 评审**：作为数据安全与隐私策略的决策依据。

### 1.2 项目背景（现状）

经过 V3.0 / V3.1 / 对话流 v2 等阶段交付，项目已具备一套**完整但「封闭」的认证子系统**：

| 能力 | 现状 | 代码位置 |
| --- | --- | --- |
| 密码哈希 | PBKDF2（盐 + 哈希，默认 10 万迭代） | `api/src/auth/password.ts` |
| 用户存储 | JSON 文件 `data/users.json`（无 DB 依赖） | `api/src/auth/user-store.ts` |
| 登录 | `POST /api/auth/login`（用户名 + 密码 → token） | `api/src/routes/auth.ts` |
| 会话 | 服务端 `createSession` / `destroySession` | `api/src/auth/session.ts` |
| 鉴权中间件 | `requireAuth` / `requireAdmin` | `api/src/middleware/auth.ts` |
| 用户管理 | `POST /api/auth/users` 等，**仅管理员可创建用户** | `api/src/routes/auth.ts` |
| 审计 | 登录 / 登出 / 用户管理写审计日志 | `api/src/auth/audit-log.ts` |
| 问答会话存储 | **服务端**落盘 `data/threads/{threadId}/`（thread/session/memory） | `api/src/engine/thread-memory-store.ts`、`docs/thread-memory-design.md` |
| 前端本地缓存 | IndexedDB `chatDb`（conversations / attachments / preferences） | `frontend/src/services/chatDb.ts` |
| 前端登录态 | token 存 localStorage，用户信息走 `/api/auth/me` 恢复 | `frontend/src/stores/auth.ts` |

**当前缺口（即本需求动因）：**

1. **无自助注册**：普通用户无法自行创建账户，只能由管理员通过 `POST /api/auth/users` 预置。这与「注册用户之间需具备数据隔离」的多用户场景不匹配。
2. **会话服务端落盘**：当前问答会话/记忆写入服务端 `data/threads/`，与本次需求「会话内容不存储于服务器端，仅在本地维护」**直接冲突**，须重新明确数据驻留模型。
3. **本地多账户隔离未定义**：IndexedDB 现有 `conversations` 存储无 `ownerId` 维度，未定义同浏览器多账户切换时的命名空间隔离规则。

### 1.3 术语定义

| 术语 | 定义 |
| --- | --- |
| **自助注册** | 任意未登录用户通过公开接口自行创建账户，无需管理员介入 |
| **简易机制** | 仅依赖「用户名 + 密码」二元凭证，不做邮箱/手机验证、验证码、双因素等增强 |
| **数据隔离** | 不同注册用户的数据彼此不可见、不可越权访问 |
| **数据驻留（Data Residency）** | 数据物理存放的位置：服务端共享区 vs 客户端本地 |
| **本地优先（local-first）** | 用户会话与个人信息以客户端本地存储为权威源，不回传服务端 |
| **ownerId** | 本地数据记录归属的账户标识（= 登录用户的 `userId`），用于本地命名空间隔离 |
| **PBKDF2** | 基于密码的密钥派生函数，用于密码哈希（盐 + 多轮迭代） |

### 1.4 范围与目标

#### 1.4.1 范围内（本需求必须）

- 公开的自助注册接口（用户名 + 密码），复用现有 PBKDF2 与用户存储；
- 登录 / 登出复用现有机制（仅补充注册入口）；
- 明确数据驻留模型：**知识库服务端共享，会话与个人信息/配置本地化**；
- 注册用户之间的数据隔离规则，含**本地多账户命名空间隔离**；
- 前端注册页与 `auth` store 注册方法；
- 将问答会话从「服务端 `data/threads/`」迁移为「客户端本地 IndexedDB」，停用服务端会话写（默认）。

#### 1.4.2 范围外（本需求不做）

- 邮箱 / 手机号验证、图形验证码、双因素认证（2FA）；
- 第三方 OAuth / SSO 登录；
- 密码找回 / 重置邮件（管理员仍可在后台重置密码）；
- 会话数据的云端同步、跨设备同步；
- 服务端对会话内容的任何读取、分析或建模。

## 2. 总体描述

### 2.1 产品定位

在保持「本地知识库 + 隐私优先」理念的前提下，向**多用户**开放：允许团队/个人自行注册账户使用，但每个用户的问答痕迹只属于他自己（本地），共享的只有知识库本身。

### 2.2 用户角色

| 角色 | 来源 | 注册方式 | 会话/配置驻留 |
| --- | --- | --- | --- |
| **普通用户（user）** | 自助注册默认角色 | 公开 `POST /api/auth/register` | 客户端本地 |
| **管理员（admin）** | 预置 / 后台创建 | `POST /api/auth/users`（管理员） | 客户端本地 |
| **游客（guest）** | 预置 | 管理员创建 | 客户端本地 |

> 自助注册**仅可创建 `user` 角色**，禁止自助成为 `admin` 或 `guest`（防止权限提升）。

### 2.3 关键设计决策（必须确认）

本需求中「注册用户之间需具备数据隔离」与「会话内容不存储于服务器端，仅在本地维护」二者结合，推导出如下**本地优先（local-first）数据驻留模型**。该模型解决了与现有 `docs/thread-memory-design.md`（服务端线程存储）的矛盾：

```
┌──────────────────────────────────────────────────────────────┐
│  服务端（共享 + 认证权威）                                       │
│   ├─ 知识库（vault + 编译索引 + 图谱）  ← 所有已认证用户可读（共享）│
│   └─ 用户凭证（username + PBKDF2 hash + salt）← 按账户隔离，仅用于认证│
└──────────────────────────────────────────────────────────────┘
                           ▲ 认证（login/register 校验）
                           │
┌──────────────────────────────────────────────────────────────┐
│  客户端本地（IndexedDB + localStorage，每台设备/浏览器）           │
│   ├─ 会话 / 问答历史（conversations store，按 ownerId 隔离）       │
│   ├─ 滚动记忆 / 草稿（本地，注入 LLM 上下文）                     │
│   └─ 用户个人配置 / 偏好（preferences store / localStorage）      │
└──────────────────────────────────────────────────────────────┘
```

**决策要点：**

1. **隔离由「本地命名空间 + 登录态绑定」实现**。由于会话不落服务端，服务端不存在跨用户的会话数据，因此「注册用户之间数据隔离」在**服务端层面天然成立**（服务端只持有与账户绑定的凭证，且无会话数据）；在**客户端层面**，通过给本地记录打 `ownerId`（= 当前 `userId`）并在所有读写路径校验 `ownerId === 当前登录 userId`，保证同设备多账户切换时不串数据。
2. **服务端 `data/threads/` 默认停用写入**。现有 `thread-memory-store.ts` 的服务端会话落盘将改为「可选/企业模式」或下线，避免与「会话本地化」冲突。具体迁移策略见 §9 与 §11。
3. **知识库始终共享**：问答检索依赖服务端共享 vault，这是唯一有意跨用户共享的数据，符合需求「知识库资料对所有用户共享」。

> ⚠️ **待确认项（D-1）**：服务端 `data/threads/` 是「默认停用 + 提供迁移脚本」还是「保留为可选开关（配置项 `serverSideThreads`）」？本文档默认采用前者（更契合隐私诉求），若需兼容存量部署可改为后者。

### 2.4 运行环境约束

- 后端：Node / Fastify（沿用现有运行时与 `data/` 落盘约定）；
- 前端：Vue3 + Pinia + Vite，浏览器环境（IndexedDB、localStorage）；
- 隐私约束：会话/配置**不得**出现任何上传/外发接口；服务端不得新增会话写接口（除可选的兼容开关）。

## 3. 功能需求

> 编号规则：`FR-RM-NN`。优先级：`P0` 必须 / `P1` 重要 / `P2` 可选增强。

### FR-RM-01 自助注册（公开接口） — P0

- **描述**：新增公开接口 `POST /api/auth/register`，未登录用户可凭「用户名 + 密码」自助创建账户，默认角色 `user`。
- **输入**：`{ username: string, password: string, confirmPassword?: string }`
- **处理**：
  1. 复用 `findUserByUsername` 校验用户名唯一性；已存在返回 `409 { error: '用户名已存在' }`；
  2. 校验用户名格式：长度 3–32，仅允许字母、数字、下划线（`/^[A-Za-z0-9_]{3,32}$/`）；
  3. 校验密码强度（简易但安全底线）：长度 8–64，禁止纯空白；建议同时禁止常见弱密码字典（P2 可选）；
  4. 若提供 `confirmPassword`，须与 `password` 一致，否则 `400`；
  5. 复用 `createUser({ username, password, role: 'user' })` 完成 PBKDF2 盐+哈希落盘；
  6. 写审计日志 `action: 'user_register'`（沿用 `audit-log`）；
  7. 注册成功后**自动创建会话并返回 token**（与 `login` 同构），实现「注册即登录」的简易体验。
- **输出（成功）**：`200 { ok: true, token, user: { id, username, role, ... } }`
- **输出（失败）**：
  - `400` 格式/一致性错误（不明确区分「用户名非法」与「密码非法」以外的细节）；
  - `409` 用户名已存在；
  - `429` 注册频率限制触发（见 FR-RM-10）。
- **约束**：该接口**不要求** `Authorization`；角色强制为 `user`，忽略请求体中任何 `role` 字段；不得通过此接口创建 `admin`/`guest`。

### FR-RM-02 登录（复用现有） — P0

- **描述**：`POST /api/auth/login` 维持现状（用户名 + 密码 → token），恒定时间验证、失败统一返回「用户名或密码错误」以防枚举。
- **约束**：本需求不改动登录逻辑，仅作为注册后的「自动登录」与独立登录入口。

### FR-RM-03 登出（复用现有） — P0

- 维持 `POST /api/auth/logout`：销毁服务端会话 token；前端清除 token 与内存用户信息。**本地会话数据保留**（按 `ownerId` 仍在本地，下次登录可见）。

### FR-RM-04 数据驻留与隔离模型 — P0

- **服务端共享且驻留**：知识库（vault、编译索引、图谱）对所有已认证用户可读，无用户维度隔离。
- **服务端驻留但账户隔离**：用户凭证（username + 哈希）按账户隔离，密码不可逆，仅用于认证。
- **客户端本地且账户隔离**：问答会话、历史消息、滚动记忆、草稿、个人配置/偏好，全部驻留客户端，按 `ownerId` 隔离。
- **服务端禁写会话**：除可选兼容开关外，服务端不再提供会话/记忆写接口；`/api/query` 的历史上下文来源由「服务端 `thread-memory-store`」切换为「前端本地注入」。

### FR-RM-05 会话本地化（迁移服务端线程存储） — P0

- **描述**：将问答会话的持久化从服务端 `data/threads/{threadId}/` 迁移到前端 IndexedDB（既有 `chatDb` 的 `conversations` store）。
- **处理**：
  1. `conversations` store 的记录结构新增 `ownerId` 字段（= 当前登录 `userId`）；
  2. 会话列表/详情/侧栏加载时按 `ownerId` 过滤，确保只呈现当前账户数据；
  3. 每轮问答的记忆注入（`## 历史对话`）改由本地读取并随请求 `history` 透传（兼容现有 `/api/query` 的 `history` 回退路径）；
  4. 归档（`POST /api/query/archive` 等）改从本地读取会话内容，不再依赖服务端 `session.json`；
  5. 服务端 `data/threads/` 默认不再写入新数据（见 §9 迁移）。
- **约束**：本地读写均为异步（IndexedDB），不引入网络往返；保留「清空记忆 ≠ 清空会话」的解耦语义（记忆可单独清、会话可单独清、线程可整体删）。

### FR-RM-06 本地多账户隔离 — P0

- **描述**：同一浏览器/设备上多账户切换时，各方会话与配置互不泄漏。
- **处理**：
  1. 所有本地记录读写前校验 `ownerId === 当前登录 userId`；不匹配则本地拒绝（视为越权，返回空/错误）；
  2. 登录/恢复会话时，仅加载 `ownerId === 当前 userId` 的数据；登出不清空本地数据，但切换账户后不再呈现上一账户数据；
  3. 未登录态（`token` 为空）不得加载任何账户会话；
  4. 前端 `conversations` store 与 `chatDb` 全部查询增加 `ownerId` 过滤参数。
- **约束**：本地存储为明文（同设备同浏览器共享同一 IndexedDB），隔离依赖「逻辑命名空间 + 登录态绑定」。如需抗同设备其他进程/用户读取，见 FR-RM-07。

### FR-RM-07 本地数据加密（可选增强） — P2

- **描述**：用 `PBKDF2(用户密码, 设备随机盐)` 派生密钥，AES-GCM 加密本地 IndexedDB 中的会话与配置记录，降低同设备数据被其他进程读取的风险。
- **触发**：仅当本需求确认纳入；否则保持明文 + `ownerId` 逻辑隔离。
- **约束**：加密密钥不离开本地；用户修改密码须触发本地数据重加密；遗忘密码将导致本地数据不可逆（须配合导出/导入，见 FR-RM-08）。

### FR-RM-08 个人信息与配置本地化 — P1

- **描述**：用户个人配置（主题、TTS 设置、模型选择、侧栏状态、偏好等）继续存储于本地（`preferences` store / localStorage），**不回传服务端**；服务端不保存任何用户画像/偏好字段。
- **处理**：清理现有代码中任何把个人配置回写服务端的路径（如有）；明确「配置归属本地」的契约。

### FR-RM-09 知识库共享可读 — P0

- **描述**：所有已认证用户（含自助注册的 `user`）均可持续访问共享知识库（vault 浏览、检索、图谱、问答）。
- **约束**：保持现有 RBAC 中 `user` 角色对知识库相关端点的权限不变；游客 `guest` 的只读策略维持现状。

### FR-RM-10 注册频率限制（防滥用） — P1

- **描述**：简易机制下，对 `POST /api/auth/register` 增加基础限流（如单 IP 10 次/分钟、单用户名探测 5 次/分钟），防止批量撞库/枚举。
- **约束**：限流为服务端内存/文件级，不引入额外中间件依赖；登录接口可复用同一限流框架（P2）。

### FR-RM-11 管理员后台创建用户（保留） — P0

- **描述**：保留 `POST /api/auth/users`（管理员专属）作为内部/批量开户通道，与自助注册并存；自助注册是公开补充，不替代后台管理。
- **约束**：后台创建的密码同样走 PBKDF2；角色可由管理员指定（admin/user/guest）。

## 4. 非功能需求

### 4.1 安全性

- **密码存储**：沿用 PBKDF2（盐随机、迭代 ≥ 10 万），服务端**只存哈希不存明文**（复用 `password.ts`）。
- **登录验证**：恒定时间比较（沿用 `verifyPassword` + 假盐），不泄露用户名是否存在。
- **注册防枚举**：用户名已存在返回 `409` 仅暴露「该用户名不可用」，不暴露其角色/是否存在于管理员列表；格式错误返回 `400`。
- **权限提升防护**：自助注册接口硬编码角色为 `user`，忽略任何传入角色字段。
- **传输**：token 经 `Authorization: Bearer` 头传递；建议在部署层启用 HTTPS（既有约束）。
- **审计**：注册、登录、登出、密码修改均写审计日志（沿用 `audit-log`）。

### 4.2 隐私与数据驻留

- **会话不出本地**：服务端不新增任何会话/记忆写接口（除可选兼容开关 D-1）；前端不向服务端发送会话全文（历史上下文以请求级 `history` 透传，不落盘）。
- **配置不出本地**：个人配置/偏好仅存本地。
- **最小暴露**：服务端数据模型仅含「凭证 + 共享知识库」，不持有可能泄露用户隐私的会话/画像数据。

### 4.3 性能

- 注册接口：含一次 PBKDF2 哈希，P95 < 800ms（沿用既有哈希开销基线）；
- 登录接口：P95 < 500ms；
- 本地会话读写：异步 IndexedDB，无网络往返，UI 感知 < 100ms（列表渲染）。

### 4.4 兼容性

- 与现有 RBAC、管理员用户管理、审计日志**并存**；
- 前端 `useAuthStore` 在保留 `login/logout/restoreSession` 的同时新增 `register`；
- 与既有 Vault / 编译 / 图谱 / 问答工作流**无破坏性改动**（仅问答历史来源切换为本地）。

### 4.5 可用性 / 易用性

- 注册页表单含前端格式校验（用户名 3–32、密码 8–64、两次一致），错误就近提示；
- 注册成功后自动登录并跳转首页（简化流程）；
- 登录页提供「去注册」入口，注册页提供「去登录」入口。

### 4.6 可维护性与可观测

- 复用既有 `user-store` / `password` / `session` / `audit-log`，不重复造轮子；
- 注册成功/失败纳入既有审计日志，便于安全审计。

## 6. 技术架构

### 6.1 受影响组件

| 层 | 文件 | 变更类型 |
| --- | --- | --- |
| 后端·路由 | `api/src/routes/auth.ts` | 新增 `POST /api/auth/register`；可选限流 |
| 后端·存储 | `api/src/auth/user-store.ts` | 复用 `createUser` / `findUserByUsername`（无需改动或仅放宽角色默认） |
| 后端·密码 | `api/src/auth/password.ts` | 复用，不改动 |
| 后端·会话 | `api/src/auth/session.ts` | 复用 `createSession`（注册自动登录） |
| 后端·线程 | `api/src/engine/thread-memory-store.ts` | 默认停用服务端写；或改造为可选开关 |
| 后端·问答 | `api/src/routes/query.ts` | 历史上下文改由请求 `history` 透传（已是回退路径），不再强依赖服务端 `getHistoryContext` |
| 前端·状态 | `frontend/src/stores/auth.ts` | 新增 `register()` 方法 |
| 前端·本地库 | `frontend/src/services/chatDb.ts` | `conversations` store 记录增加 `ownerId`；查询增加 `ownerId` 过滤 |
| 前端·会话 | `frontend/src/stores/conversations.ts` | 所有读写注入/校验 `ownerId` |
| 前端·页面 | `frontend/src/views/Register.vue`（新增）/`Login.vue`（扩展） | 注册/登录入口 |
| 前端·侧栏 | `frontend/src/components/ConversationSidebar.vue` | 按 `ownerId` 展示 |
| 文档 | `docs/thread-memory-design.md` | 标注「服务端会话存储」被本需求部分取代（会话本地化） |

### 6.2 数据流（注册 → 会话本地化）

```
[注册] 前端 Register.vue
   └─ POST /api/auth/register {username,password}
        └─ 后端：findUserByUsername 校验 → createUser(PBKDF2) → createSession → 审计
        └─ 返回 {token, user}  → 前端 auth.store.register() 存 token + 自动登录

[问答] 前端 Query.vue
   └─ 本地 chatDb 按 ownerId 读取历史 → 随 /api/query 的 history 透传
   └─ 答案返回 → 本地 chatDb 写入（带 ownerId）→ 本地记忆滚动裁剪
   （服务端不落会话，仅基于共享知识库检索 + 请求级 history）
```

## 7. 接口与数据结构

### 7.1 新增接口：`POST /api/auth/register`

**请求**
```json
{
  "username": "alice",
  "password": "Str0ng#Passw0rd",
  "confirmPassword": "Str0ng#Passw0rd"
}
```

**响应（成功 200）**
```json
{
  "ok": true,
  "token": "<jwt-like-session-token>",
  "user": {
    "id": "uuid-v4",
    "username": "alice",
    "role": "user",
    "enabled": true,
    "createdAt": "ISO8601",
    "updatedAt": "ISO8601",
    "lastLoginAt": "ISO8601",
    "permissions": ["query", "vault.read", "..."]
  }
}
```

**响应（失败）**
```json
{ "error": "用户名已存在" }        // 409
{ "error": "用户名须为 3-32 位字母数字下划线" } // 400
{ "error": "密码长度须为 8-64 位" }     // 400
{ "error": "两次输入的密码不一致" }     // 400
{ "error": "注册过于频繁，请稍后再试" }  // 429
```

**校验规则汇总**

| 字段 | 规则 |
| --- | --- |
| username | `/^[A-Za-z0-9_]{3,32}$/`，全局唯一，忽略 `role` 传入 |
| password | 长度 8–64，禁止纯空白；（P2）弱密码字典拦截 |
| confirmPassword | 若提供须等于 password |
| role | 固定 `user`，不接受客户端指定 |

### 7.2 前端本地存储结构（变更）

**IndexedDB `conversations` store（keyPath `id`）** — 在现有字段上新增 `ownerId`：

```jsonc
{
  "id": "uuid-v4",
  "ownerId": "user-uuid",          // 新增：归属账户，本地隔离主键
  "title": "新会话",
  "messages": [ { "question": "…", "answer": "…", "refs": ["页面名"], "ts": "ISO8601" } ],
  "memory": [ { "role": "user", "content": "…", "ts": "ISO8601" } ],
  "isPinned": false,
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "preview": "最近一条回答前 60 字"
}
```

**`preferences` store（keyPath `key`）** — 继续存放主题、TTS、模型、侧栏等，本地化，不回传。

> 注：`ownerId` 取值为登录用户的 `userId`（来自 `/api/auth/me` 或登录响应），在 `auth` store 恢复会话后可用。

## 8. 验收标准

| 编号 | 验收项 | 预期结果 |
| --- | --- | --- |
| AC-RM-1 | 未登录访问 `/api/auth/register` | 可访问并成功创建账户，服务端 `data/users.json` 仅存 PBKDF2 哈希 |
| AC-RM-2 | 重复用户名注册 | 返回 `409 { error: '用户名已存在' }`，不泄露该用户角色 |
| AC-RM-3 | 非法用户名（如 `ab` 或含空格） | 返回 `400` 格式错误 |
| AC-RM-4 | 弱密码（长度 < 8） | 返回 `400` 密码长度错误 |
| AC-RM-5 | 两次密码不一致 | 返回 `400` 不一致错误 |
| AC-RM-6 | 注册响应中尝试传 `role: 'admin'` | 实际创建角色仍为 `user`，返回 `user` |
| AC-RM-7 | 注册成功后 | 返回 token，前端自动登录并跳转，无需再次登录 |
| AC-RM-8 | 用户 A 注册并问答若干轮（本地） | `chatDb` 中会话记录的 `ownerId === A.userId` |
| AC-RM-9 | 登出 A，登录 B | 侧栏/列表仅呈现 B 的数据，A 的历史不可见；反之登回 A 后 A 数据恢复可见 |
| AC-RM-10 | 重启浏览器 / 断网 | 本地会话与配置仍在（IndexedDB 持久化） |
| AC-RM-11 | 服务端 `data/threads/` | 默认不产生新线程目录（或按 D-1 开关配置） |
| AC-RM-12 | 知识库共享 | A、B 均能正常检索/浏览/问答同一知识库 |
| AC-RM-13 | 审计日志 | 注册 / 登录 / 登出均写入 `audit.log` |
| AC-RM-14 | 限流（FR-RM-10） | 单 IP 超频触发 `429` |
| AC-RM-15 | 兼容性 | 管理员 `POST /api/auth/users` 仍可用，RBAC 与既有工作流无回归 |

## 9. 风险与依赖

| 风险 / 依赖 | 描述 | 缓解 |
| --- | --- | --- |
| **R-1 与服务端线程存储矛盾** | 现有 `thread-memory-design.md` 将会话落服务端，与「会话本地化」冲突 | 默认停用 `data/threads/` 写入（D-1）；提供迁移脚本把存量 `data/threads` 导入本地（§11 阶段 2）；相关设计文档标注被取代 |
| **R-2 本地数据丢失** | 清缓存 / 换设备 / 重装浏览器导致会话不可恢复 | 提供「会话导出 / 导入」本地文件（P2，FR-RM-08 伴随）；明确告知用户本地存储风险 |
| **R-3 同设备明文隔离不足** | 未加密时，同设备其他进程/用户可读 IndexedDB | 纳入 FR-RM-07 本地加密（P2）；短期以 `ownerId` 逻辑隔离 + 登录态绑定兜底 |
| **R-4 注册滥用 / 撞库** | 公开注册可能被批量探测 | FR-RM-10 限流；审计日志监控 |
| **R-5 历史上下文连贯性** | 问答记忆由服务端注入改为本地透传 `history` | 复用现有 `/api/query` 的 `history` 回退路径；前端保证每轮附上本地记忆 |
| **R-6 多账户切换竞态** | 快速登出/登录切换时可能读取到上一账户残留 state | `auth` store 恢复/清除时同步重置 `conversations` store 的内存态与过滤条件 |

- **local-first**：用户会话与配置以客户端为权威源，不回传服务端。
