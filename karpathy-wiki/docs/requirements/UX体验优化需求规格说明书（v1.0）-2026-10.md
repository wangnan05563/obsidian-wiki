## 2. 总体描述

### 2.1 目标

1. **主路径可读**：用户不 hover、不试错也能看懂主操作与当前状态。
2. **入口可达**：15 个菜单在桌面端全部可达，移动端「我的」能查到完整功能清单。
3. **数据不打架**：同一指标只有一个口径；两套历史明确区分；数字有时点。
4. **失败不静默**：启动、编译、保存、分析失败都能看到原因与下一步。
5. **长任务可控**：批量操作可预估、可暂停、可续跑、可取消。
6. **首次上手可走通**：登录页不泄露默认口令，帮助文档路径与真实界面一致。
7. **规范可复用**：StateBlock、IconActionButton、确认矩阵、术语表成为后续开发基线。

### 2.2 非目标

- 不重做整体视觉风格与品牌；
- 不引入前端路由框架、不重构状态管理；
- 不改变核心业务模型（页面/资料/编译/图谱的数据结构）；
- 不承诺自动翻译用户上传技能的英文描述；
- 不以本 PRD 替代后端接口设计文档；涉及后端的新增能力在需求内标注依赖。

### 2.3 用户角色与场景

| 角色 | 典型场景 | 本 PRD 关注点 |
|---|---|---|
| 新用户（guest） | 首次登录 → 按帮助配置 → 投递第一篇资料 | A1/A4、D1x、I1、X7、术语一致性 |
| 高频用户 | 问答、浏览、图谱、编译 | Q1–Q9、G1/G2、P2–P8、N4 |
| 管理员 | 体检、批量修复、配置、用户、穿透 | H1/H2、C1–C6、T1–T5、A1/U3 |
| 移动端用户 | 问答、浏览、投递、聆听 | M1（「我的」完整功能清单） |

### 2.4 设计原则

1. **主操作必须有文字**：图标可以保留，但主 CTA 必须是「图标 + 动词 + 对象」；纯图标仅限高频工具栏且有 aria-label 与 tooltip。
2. **单一可信源**：术语、状态中文映射、编译阶段常量、页面总数、图标按钮组件各只有一处定义。
3. **三态显式**：所有异步区域区分「加载中 / 无内容 / 加载失败」，失败必带原因与重试。
4. **风险分级确认**：可撤销操作不阻塞（undo toast）；写盘/覆盖/产生费用必确认；不可逆操作确认文案包含对象数量与影响。
5. **失败不静默**：禁止只 `console.warn` 或只回退视图；用户必须看到一次可见反馈。
6. **成本透明**：调用 LLM 的批量操作在启动前展示「预计次数 / 约 tokens / 预计时长」，并标明是估算。
7. **渐进增强**：hash 深链不引入 vue-router；移动端保留现有结构，只补入口清单。
8. **改动可回滚**：按批次独立提交；批次 3/5 与已完成的「全站图标按钮」「统一弹窗 AppModal」改造先做差集，不重复造轮子。

### 2.5 优先级与验收口径

| 优先级 | 定义 | 验收要求 |
|---|---|---|
| P0 | 阻断核心路径 / 误导决策 / 首屏受挫 / 数据自相矛盾 / 失败静默 | 本迭代必须完成，逐条实测通过 |
| P1 | 明显增加操作或认知成本，有绕行 | 下一迭代完成，逐条实测通过 |
| P2 | 打磨项 | 不进入 v1，随批次顺带，不单独验收 |

验收环境：本地 `api` + `vite`，Chrome/Edge 最新两个大版本，视口至少覆盖 1440×900 与 1280×720；管理端与普通用户各走一遍。涉及数据的验收使用库内真实数据（当前约 245 图谱节点 / 216 扫描页面 / 597 体检问题）。

## 4. 详细需求

### 4.1 Epic A：导航与信息架构（批次 1 / T02326）

#### R-A1 导航分组与全量可达

- 优先级：P1
- 覆盖：N1、N2、M1
- 现状：15 项平铺；1258×566 下侧栏只能显示 9 项，滚动条仅 4px、无渐隐提示；移动端只剩 5 个 tab，其余 10 个功能无入口说明。
- 需求：
  1. 桌面侧栏分 4 组 + 底部固定区：**工作台**（仪表盘、知识问答）、**知识生产**（投递资料、编译进度、知识浏览、知识图谱）、**质量与运维**（体检中心、页面质量清洗、缓存与日志清理、内网穿透）、**系统管理**（配置中心、用户管理、技能管理）；帮助文档、关于固定在底部。
  2. 分组标题可点击折叠，折叠状态按用户记忆；权限过滤后为空的组不渲染。
  3. 侧栏内容溢出时显示底部渐隐遮罩与「↓ 还有 N 项」提示；不使用纯 4px 滚动条作为唯一提示。
  4. 移动端「我的」tab 增加完整功能清单：可直接跳转的只读项可跳；管理项标注「请在桌面端使用」，不得让用户误以为功能缺失。
- 验收：
  - 1440×900、1280×720、1258×566 三种视口下，组标题全部可见，15 项均可通过滚动 + 折叠到达；Tab 键可逐个聚焦；
  - 侧栏溢出时渐隐与剩余项数提示可见；
  - 移动端「我的」能查到全部 15 个功能及可用性说明；
  - 普通用户看不到无权限菜单，且不出现空组。
- 依赖：无。注意与批次 2 的菜单改名同步（缓存与日志清理、页面质量清洗）。

#### R-A2 Hash 深链与刷新恢复

- 优先级：P1
- 覆盖：N4
- 现状：无 vue-router，视图由 `currentView` 切换；刷新、回退、分享均丢失当前视图。
- 需求：
  1. 用 hash 同步一级视图：`#/dashboard`、`#/ingest`、`#/progress`、`#/browse`、`#/query`、`#/graph`、`#/health`、`#/config`、`#/tunnel`、`#/cleanup`、`#/users`、`#/skill`、`#/help`、`#/dataclean`、`#/about`。
  2. 启动时解析 hash 并恢复视图；未知/无权限 hash 回落到仪表盘并给出一次提示。
  3. 浏览器前进/后退可用；复制 URL 到新标签可打开同一视图。
  4. v1 不同步视图内 tab（如配置中心的具体 tab），后续再扩展。
- 验收：在「帮助文档」刷新仍停留帮助文档；回退回到上一视图；复制 `#/query` 到新标签打开问答；`#/not-exist` 回落仪表盘且有提示；不引入 vue-router 依赖。
- 依赖：无。

#### R-A3 导航可访问性与权限反馈

- 优先级：P1
- 覆盖：N3、N6、N7
- 现状：当前项无 `aria-current`；无权限跳转只 `console.warn`；用户管理与关于复用同一图标，技能管理复用配置图标。
- 需求：
  1. 当前菜单加 `aria-current="page"`，与移动端现有做法一致。
  2. 权限拦截必须给可见反馈：toast「该功能仅管理员可用」或禁用态 + 原因；不再静默回退。
  3. 15 个菜单配齐互斥图标；同一组内不得复用图标；图标语义与组名呼应。
- 验收：可访问性树中当前项 `aria-current=page`；无权限操作 100% 有可见提示；15 个图标两两不同；键盘聚焦有可见焦点环。
- 依赖：无。

#### R-A4 悬浮问答不遮挡首屏

- 优先级：P1
- 覆盖：N8
- 现状：展开态写入 localStorage，跨会话保留；重新进入即展开并遮挡仪表盘右半屏；关闭控件存在残留观察（未稳定复现，不纳入验收）。
- 需求：
  1. 展开态改为会话级记忆（sessionStorage）：浏览器新会话默认收起，页内刷新可保持展开。
  2. 展开面板宽度上限 400px，不得覆盖左侧菜单与页面主 CTA；1280×720 下打开面板后主内容仍可操作。
  3. 支持 ESC 收起；关闭按钮在面板内部，带 aria-label，随面板卸载。
  4. 首次进入用 FAB 上的一次性红点/引导提示可展开，不自动展开。
- 验收：关闭浏览器重开后为收起态；页内刷新保持原状态；1280×720 打开面板不遮挡菜单与主 CTA；ESC 可收起；无游离关闭气泡。
- 依赖：无。

#### R-A5 配置中心二级导航

- 优先级：**P0**
- 覆盖：C2
- 现状：11 个 tab 单行平铺，横向溢出，最后一个只显示「Prom」；默认 tab 为 SCHEMA 规范。
- 需求：
  1. 改为左侧二级导航（≥1200px）或分组 tab（<1200px），分 3 组：
     - 个人偏好：朗读设置、界面主题；
     - AI 服务：AI 服务、共享AI、Prompt IDE；
     - 系统：SCHEMA 规范、系统配置、数据迁移、MCP 接口、工具配置、QQ 导入。
  2. 11 个标签完整可见，不截断、不依赖 ‹ › 箭头；活动项有明确底色/左侧标记。
  3. 分组标题不可作为 tab 选中；键盘可遍历。
  4. 与 R-F3 的权限 tab 策略配合：无权限 tab 可见但禁用并标注「仅管理员」。
- 验收：1024px 宽度下 11 个标签全部完整显示；无横向滚动条；活动态清晰；非管理员看到 4 个可用 + 7 个禁用标签。
- 依赖：无。

## 5. 非功能需求

### 5.1 性能

- 视图切换 ≤300ms；仪表盘首屏数据 ≤2s（本地）。
- 体检 597 项列表分页/虚拟滚动后单页渲染 ≤300ms；搜索/筛选响应 ≤300ms。
- 图谱 245 节点默认聚合/Top-N 视图 1s 内可交互；全图模式允许更慢但必须有加载态。
- 长任务（批量修复、编译）不得阻塞主线程；进度更新频率≤2 次/秒。

### 5.2 可访问性

- 新增/修改组件达到 WCAG 2.1 AA 的相关项：键盘可达、焦点可见、aria-label/aria-current/aria-selected 正确、对比度不降低。
- 全屏遮罩支持 ESC；弹窗/抽屉焦点闭环；图标按钮不得只有 `title`。
- 状态变化（批量进度、保存结果）使用 `aria-live="polite"` 播报。

### 5.3 兼容性

- 桌面：Chrome/Edge 最新两个大版本；最低 1280×720，目标 1440×900。
- 移动端：沿用现有 <768px MobileShell；本次只补「我的」功能清单，不新增中间断点。
- 不引入 vue-router；hash 方案需兼容直接打开与前进/后退。

### 5.4 安全

- 非本地模式不显示默认口令；新增 `/api/meta` 仅只读、无密钥、无用户数据。
- 所有密钥输入保持 password + show-password；导出继续脱敏。
- 新增/修改的危险操作必须有确认；确认文案含对象与影响。
- 不新增未鉴权的写接口；批量任务接口沿用现有鉴权与权限守卫。

### 5.5 可维护性

- 单一来源：术语表、状态中文映射、编译阶段常量、页面总数、IconActionButton、StateBlock。
- 禁止新增第二套 API 客户端；统一 `apiFetch`/`authFetch`。
- 批次 3/5 开工前先比对已完成的图标按钮/AppModal 改造，只做差集。
- 用户可见字符串不出现裸英文枚举；新增文案需进术语表检查。

### 5.6 文案与反馈

- 全站用户可见文案中文；技术词进 tooltip。
- 加载/空/错误三态文案独立，不复用「加载中」表达「无内容」。
- 失败反馈包含：发生了什么、可能原因、下一步动作；禁止只 console。

2. 高频用户：问答排队/停止/重新生成 → 浏览筛选 → 图谱搜索/打开页面 → 刷新保持视图。
3. 管理员：体检筛选/批量修复暂停续跑 → 配置生效徽标/待重启 → 穿透自检/失败提示 → 用户保护/种子账户。
4. 移动端：底部 tab → 「我的」完整功能清单。

### 7.2 风险

1. **245/216 根因未知**：若差异来自索引陈旧，仅加标签会掩盖问题；T02329 需先定位再决定是否修索引。
2. **图谱聚合改变分析语义**：默认 Top-N 可能让用户以为数据变少；必须保留「查看全图」并显示节点/链接总数。
3. **改名影响帮助锚点与外部链接**：S5/L7 改名后需全量检查锚点、提示语、文档；发布说明公告。
4. **配置生效元数据缺失**：前端映射表容易与后端脱节；需加测试或在后端补元数据。
5. **批次重叠**：批次 3/5 与已完成的图标按钮/AppModal 改造有交集，开工前先做差集，避免回滚他人改动。
6. **并发会话**：仓库可能存在其他会话的未提交改动；每批独立 pathspec 提交，不 `git add -A`。
7. **A1 安全改造**：隐藏提示只是表面修复；种子账户仍启用时风险仍在，必须同时做停用/改密提示。
8. **H2 假续跑**：若后端只保存前端进度而无检查点，刷新后会重复调用 LLM 计费；验收必须验证「不重复已成功项」。

### 7.3 开放问题（PRD 评审需拍板）

1. **A1 机制**：新增公开 `/api/meta`（推荐，便于后续版本信息）还是仅构建期 DEV 标记？
2. **N4 hash 格式**：`#/view`（本 PRD 基线）还是 `#/view?tab=`（同步视图内 tab）？
3. **Q5 可恢复流停止**：FloatingChat 停止是否必须调用 `/query/stop`（涉及计费语义）？本 PRD 暂按「与 Query 对齐」；后端不支持时按 R-C4 降级为「退订」。
4. **术语表落点**：`docs/术语表.md` 是否同时作为帮助文档数据源（避免两处维护）？建议是，并加发布前一致性检查。
