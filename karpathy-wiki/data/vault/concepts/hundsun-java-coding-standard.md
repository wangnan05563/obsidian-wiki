# 恒生电子 Java 编码规范

**恒生电子 Java 编码规范**是 [[恒生电子]]（Hundsun Technologies）为其 Java 开发者制定的编码规范文档，旨在为全公司 Java 程序的开发者提供规范化指导，适用于程序员个人编译环境以及研发团队集成环境等场合的代码规范化检查。

## 概述

本规范由恒生电子 EPG 研发组编制，批准日期为 2023/03/15，密级为内部。规范覆盖了从命名风格、常量定义、代码格式到 OOP 规约、集合处理、并发处理、异常处理、日志规约等全方位的编码要求。

## 术语定义

| 术语 | 解释 |
|------|------|
| **POJO** | Plain Ordinary Java Object，专指只有 setter/getter/toString 的简单类，包括 DO/DTO/BO/VO 等 |
| **GAV** | GroupId、ArtifactId、Version，Maven 坐标，唯一标识 jar 包 |
| **OOP** | Object Oriented Programming，类、对象的编程处理方式 |
| **ORM** | Object Relation Mapping，对象关系映射（如 Hibernate, MyBatis） |
| **NPE** | java.lang.NullPointerException，空指针异常 |
| **OOM** | Out Of Memory，JVM 内存不足的严重状况 |
| **SOA** | Service-Oriented Architecture，面向服务架构 |
| **一方库** | 本工程内部子项目模块依赖的库 |
| **二方库** | 公司内部发布到中央仓库，可供公司内部其它应用依赖的库 |
| **三方库** | 公司之外的开源库 |

## 约束等级

| 等级 | 约束效力 | 强制性 |
|------|----------|--------|
| **【强制】** | 违反该项将被认为代码存在严重缺陷 | 全公司所有 Java 编码团队必须遵守 |
| **【推荐】** | 违反该项即被认为代码存在轻微缺陷 | 各团队根据产品特性选择性地遵守 |
| **【参考】** | 违反该项可被认为代码存在优化空间 | 从产品持续优化及人员技能提升角度参考使用 |

## 编码规约摘要

### 1. 命名风格

- **【强制】** 命名不能以下划线或美元符号开始/结束
- **【强制】** 严禁使用拼音与英文混合方式
- **【强制】** 类名使用 UpperCamelCase（如 `MarcoPolo`, `UserDTO`）
- **【强制】** 方法名、参数名、变量使用 lowerCamelCase
- **【强制】** 常量命名全部大写，单词间用下划线隔开
- **【推荐】** 抽象类命名以 Abstract 开头，异常类以 Exception 结尾，测试类以 Test 结尾
- **【强制】** POJO 类中布尔类型变量不加 is 前缀
- **【强制】** 包名统一小写，点分隔符间有且仅有一个自然语义单词
- **【推荐】** 命名体现设计模式（如 `OrderFactory`, `LoginProxy`）
