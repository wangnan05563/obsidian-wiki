# HUI 工程结构规范

## 概述

HUI 工程结构规范定义了 [[hui-framework]] 项目的主工程及子工程的目录组织方式，确保项目结构清晰、可维护。

## 常规通用结构

前端项目通常遵循以下通用结构原则：
- 源代码与构建产物分离
- 静态资源统一管理
- 组件按功能模块划分

## HUI 主工程结构

HUI 主工程采用模块化目录结构，主要包含：
- **源代码目录**：存放所有业务源码
- **公共组件目录**：存放可复用的 UI 组件
- **静态资源目录**：存放图片、字体等静态资源
- **配置文件**：项目构建与运行配置

## 子工程目录结构

子工程遵循与主工程一致的目录规范，确保多工程协作时的统一性：
- 独立的组件目录
- 独立的页面/视图目录
- 统一的路由配置
- 统一的状态管理

## 规范要点

- 文件夹使用 kebab-case（短横线分隔）命名
- 组件文件使用 PascalCase 命名
- 目录层级不宜过深，推荐不超过 3 层
