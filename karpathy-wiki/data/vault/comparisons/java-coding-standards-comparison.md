# Java 编码规范对比

本文对比主流 Java 编码规范，帮助开发者理解不同规范之间的共性与差异。

## 对比表

| 维度 | [[恒生电子 Java 编码规范]] | [[阿里巴巴 Java 开发手册]] | Google Java Style |
|------|------------------------|-------------------------|-------------------|
| **发布方** | 恒生电子 | 阿里巴巴 | Google |
| **语言** | 中文 | 中文 | 英文 |
| **约束等级** | 强制/推荐/参考 | 强制/推荐/参考 | 强制/建议 |
| **命名风格** | 驼峰 + 特例 | 驼峰 + 特例 | 驼峰 |
| **OOP 规约** | 详细 | 详细 | 基本 |
| **并发处理** | 详细 | 详细 | 基本 |
| **异常处理** | 详细 | 详细 | 有 |
| **日志规约** | 详细 | 详细 | 无 |
| **二方库依赖** | 详细 | 详细 | 无 |
| **IDE 配置** | 有（IDEA/Eclipse） | 有（IDEA/Eclipse） | 无 |

## 共性

- 均使用驼峰命名（UpperCamelCase 类名，lowerCamelCase 方法/变量）
- 均强调代码可读性和可维护性
- 均对集合、并发、异常等有专门章节
- 均支持 IDE 插件自动化检查

## 差异

- 恒生规范增加了更多企业级特有的实践要求（如二方库依赖管理）
- 阿里巴巴手册最为全面，社区影响力最大
- Google Java Style 最为简洁，偏向代码格式层面
